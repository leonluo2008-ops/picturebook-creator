## 铁律 A：三件套首次输入也必须出 L1（2026-07-23 camphor 实测）

**触发场景：** 用户首轮就给了完整三件套（目标单词 + 目标年龄 + 画面风格），没有任何前置问询。

**反模式（实测触发）：**
```
用户: "目标单词：Camphor / 目标年龄:3-6 / 蜡笔手绘童趣风"
agent: （跳过 L1，直接出 L2 嵌合 4 候选 ABCD）
用户: "请你严格按照领读绘本skill来"
agent: （补 L1）
用户: "目标单词：Camphor / 目标年龄:3-6 / 蜡笔手绘童趣风"（再次重发三件套）
```

**正模式：**
```
用户: "目标单词：Camphor / 目标年龄:3-6 / 蜡笔手绘童趣风"
agent: （立刻 L1 需求确认，7 字段代码块）
用户: "确认"
agent: （L2 页面结构）
用户: "确认"
agent: （L3 标题+简介+完整 9 行旁白）
```

**铁律原文：**
> 即使用户首轮就给了完整三件套，**仍必须独立输出 L1 需求确认表**并等用户确认，才能进入 L2。"三件套齐了 ≠ L1 可省"。

## 铁律 B：L3 修边后必须给完整 9 行（2026-07-23 camphor 实测）

**触发场景：** L3 阶段用户逐句修边（"第X句换中文"/"第X句换语境"/"第X句换成X"）。

**反模式（实测触发）：**
```
用户: "第2句换成樟树，第8/9句换语境"
agent: （只输出第2句新版本 + 第8/9句 A/B/C/D 候选，未补完整 9 行）
用户: "请严格按照skill规范输出完整旁白"
agent: （补完整 9 行）
```

**正模式：**
```
用户: "第2句换成樟树，第8/9句换语境"
agent: （立即出 L3 完整 9 行旁白：标题 + 简介 + 9 行表格，含修改后的新版本）
用户: 选标题 + 简介 → 接 L4
```

**铁律原文：**
> L3 阶段用户逐句修边时，**每轮都必须给完整 9 行旁白**，不要只输出修改后的单句。完整 = 标题备选 + 简介备选 + 旁白表格全 9 行。

## 铁律 C：用户给具体末句 = 直采用，不要给 A/B/C/D 4 候选

**触发场景：** L3 末句修边时用户主动给出完整末句（不是"换语境"）。

**实测触发：**
```
用户: "第9句换成夕阳下是樟树"
```

**正模式：** 直接采用用户给的末句嵌入第 9 行，不要给 4 候选。这是 picturebook-confirmation-protocol 的延伸协议：用户给具体词 = 直采用，4 候选反而是冗余选项。

**反模式（应避免）：** 收到具体末句后仍给 A/B/C/D 候选让用户选 → 用户暴怒"我都说要夕阳下是樟树了还选什么"。

## 铁律 D：第 9 句严禁占位符（2026-07-22 双重沉淀，本会话延伸）

**继承自 memory 已沉淀铁律（07-22 两次反馈）：**
- L3 末句第 9 行严禁任何占位符（如"末句直接生成好"/"(待选)"）
- 默认直接生成 1 个最佳版（用户说"末句直接生成好，不要再给 A/B/C/D 4 候选"）
- **反触发：** 用户主动说"换语境/模板化" → 仍给 4 候选

**本会话实测：** 第 9 句用户给了具体末句"夕阳下是樟树" → 直接嵌入表格，不要任何 A/B/C/D。
