# 批量排产模式 SOP（2026-09-18 测试批 B001-B005 实测沉淀 · 第三模式）

> **定位**：从词库到批量 L1-L3 交付物的调度层。规则单源不变——创作质量规则全部在既有锚文件，本文件只管「批量怎么排、怎么防同构、怎么交付」。
> **实测**：B001-B005 两轮迭代（用户抓「X呀X」同构开场 + 标题必须三备选），检测器 batch_check 对抗验证通过。

## 一、输入资产（skill 自带）

| 资产 | 路径 | 说明 |
|---|---|---|
| 词库 | `data/vocab/dolch.csv`（315）+ `fry_1-300.csv`（300） | 重叠 193 → 去重 422 词 |
| 台账生成器 | `bin/gen_schedule.py` | 参数化：词表/月数/seed 可传 |
| 批量质量闸门 | `bin/narration_quality_check.py` 的 `batch_check()` | 同批开场骨架查重 |

## 二、五步流程

**① 排台账**：跑 `bin/gen_schedule.py`（或人工按词型月度分配），产物**直接导入 Notion 台账**（`import <csv>`，导入后 CSV 即弃——Notion 是唯一中控，CSV/排产产物一律不入仓）。台账列：排产号/月/核心词/词型分类/绑定形态/标题草案/备选标题草案/库内撞名/链形建议/画风建议/轮次/状态。

**② 领册**：两种模式并存。**工单模式（逐册，09-20 新增）**：用户在 Notion 把素材行手动置「待预处理」=下预处理工单 → Agent 收到「处理待预处理工单」类消息后跑 `preprocess --list` 列单、`preprocess --claim` 领单（自动勾「Agent预处理中」防重复创作）→ 按③创作 → `push` 入台账（自动翻「待审核」+清勾）。**批量模式**：每批 5-10 册，三件套经 `push` 直推置「待审核」。两模式殊途同归后：用户审核裁决（手动置「已审核」）→自动化转「已排产」→ Agent 走 `poll` 领取（协议见 `notion-kanban-sop.md`）。双机约定：preprocess 仅本机执行（Notion API 无 CAS，防双机重复创作）。

**③ 批量出 L1-L3**：每册三件套 = **标题备选（≥3）+ 简介备选（3-4 方向）+ 双语旁白（8-12 句）**。创作规则（绑定形态唯一性/三许可/质感四问/末句备选制）全部按既有锚文件执行，本模式不豁免任何一条。**三条硬契约**：①md 头部必须写「创作模型: <模型名>」行（push 闸门校验，非 Gemini/GPT 系拒收——09-10 创作红线）；②三件套格式严格沿用 push 解析契约（H2 行式 `## B00X · 词（链形）· 开场型：型` + 三列旁白表，0 册解析=拒收）；③**旁白中文列 = 「中文短语，英文核心词块挂末尾」**（如 `小狗会跑，can run!`——领读机制本体，纯中文翻译=事故，`binding_check` 机械闸门拦截，09-20 B011-B018 首版全批纯中文翻译事故定版），否则 push 直接失败。

**④ 批量质量闸门（本模式特有，单册模式没有的）**：

- **开场查重**：同批各册 row1 过 `batch_check()`，骨架重复 = 必须重写。开场型轮换池：场景引入/声音开场/拟声动作/悬念提问/悬念人称/对话召唤/感叹提名/动作进行——同批零复用
- **标题三备选**（每册必给）：备选 1 = 正译主标题《X · Word》；备选 2/3 必须换结构角度（数量式/场景式/拟声式/对话式/悬念式/情感式轮换），禁同构换词；**每条备选必须显示核心词**（`title_check` 机械闸门，拟声式/场景式同样不得隐去英文词——09-19 用户拦下《滴答滴答 · Tick Tock》）。原因：库内是否已有同名单词书只有用户知道——备选是用户审核排程时的选择权
- **末句查重**：同批各册末句形态人工比对（互动CTA/收束否定/归位/情感落点轮换），「I love…」型禁 2 册同批
- **链形查重**：同批 5 册 5 链形互不相同，且与已交付批零复用

**⑤ 交付**：批量文档 = 每册一节（标题备选→简介备选→旁白表→L4 工单），头部写明台账来源与机械诊断结论。**Notion 中控台在轨时**：`notion_kanban.py push <md>` 将每册转成台账单册页面（六段结构）+ 备选列回填，交付与审读确认在 Notion 完成；L4 提示词经 `deliver` 写回页面并置已交付。细节见 `notion-kanban-sop.md`。无中控台时交付 OneDrive 交接区或按用户指定位置，回读验证。

## 三、与其他模式的关系

- **单册领读模式**：台账中某册单独重做/加做时走单册流程，无批量闸门
- **词族批量模式**（fruit-series-batch-pattern 等 20 文件）：主题词族成批创作时的题材发散指引；本 SOP 的排产闸门叠在其上，两者不互斥
- **规则冲突**：一切创作质量规则以锚文件为准，本文件被锚文件压制

## 四、实测教训（勿回退）

1. 「X呀X，word!」生成器隐性模板——批量交付前必须跨册比对 row1，肉眼比不出的交给 batch_check
2. 「拟声式允许隐去核心词」旧豁免（09-19 作废）——每条标题备选过 title_check，任何结构式都不得丢英文核心词
3. 备选标题伪异构（回家的路/弯弯的路=同构）——备选按「结构角度」轮换，不是换形容词
4. 末句同构（I love X! 三连击）是 2026-09-18 get/do/make 实测旧病，批量时同病复发率最高，交付前专项查
