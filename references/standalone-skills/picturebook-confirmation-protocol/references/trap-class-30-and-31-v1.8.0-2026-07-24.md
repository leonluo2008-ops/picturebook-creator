## ⚠️ 第三十类陷阱:「改中文」→ 自动重写英文匹配对位铁律(v1.8.0 NEW · 2026-07-24 longan/pomelo/bush 三本实测新增 · 覆盖原"改中文不动英文"协议)

### 用户实测触发信号
- 2026-07-24 longan 用户原话:`第4句换成龙眼树撑起翠绿的树叶,第6句换成龙眼树长出小绿果,第9句换成龙眼树藏满了惊喜`
- 2026-07-24 pomelo 用户原话:`第4句换成柚子树撑起深绿叶,第8换成柚子树挂满大柚子,第5句换成柚子树下能乘凉第6句换成柚子树开满白花,第7句换成柚子树闻起来香香的`
- 2026-07-24 bush 用户原话:`第9句换成灌木丛真漂亮`

### 协议(必须遵循 · 升级 v1.8.0 · 覆盖原"改中文不动英文"协议)

**情况 A:用户给的"换中文"是同义/近义替换**
- 例:`第5句换成天鹅的脖子长长的`("颈长" → "脖子长" 是同义替换)
- 处理:**只改中文,英文原文保持不变**

**情况 B(v1.8.0 NEW · 高频实测 · 默认走此协议):用户给的"换中文"在语义/主题方向上与英文原文不一致**
- 例:用户给"灌木丛真漂亮"替换英文 `Bushes are cozy!` → cozy = 舒适 / 漂亮 = pretty → 跨语言不对位
- 例:用户给"长在沙漠里"替换英文 `Stars shine in the desert sky` → 整句主题反了
- 处理(**agent 必须自动改英文匹配中文对位,不允许再 A/B/C 反问用户**):
  1. **不要再追问 A/B/C 选哪个**——用户实测不耐反复问
  2. **直接改写英文匹配中文**:保持核心词结尾绑定不变,重写英文使主题对位
  3. 默认模板:
     ```
     A = 保持英文 cozy / 中文改成"灌木丛真舒服"(避让中文)
     B = 改英文匹配"漂亮" → `Bushes are so pretty!`(让英文迁就中文)
     ```
     → 默认走 **B**(用户偏好"字面给的中文就保留"——longan/pomelo/bush 三本实测都是按 B 处理的)
- 反模式(**禁止**):
  - ❌ 收到"换中文"指令就机械"只改中文"——会导致 8/9 行中英主题错位
  - ❌ 反问用户"选 A 保留英文 / B 改英文 / C 接受不对位"——浪费用户耐心
  - ❌ 默默按字面执行中英不对位——用户实测会立即反馈

### 实测处理路径(longan/pomelo/bush 三本沉淀)

| 用户指令 | 英文原文 | 用户中文 | 跨语对位? | 处理 |
|---------|---------|---------|----------|------|
| `bush P9 换成灌木丛真漂亮` | `Bushes are cozy!` | 灌木丛真漂亮 | ❌ cozy ≠ pretty | **改英文** `Bushes are so pretty!` |
| `pomelo P9 换成柚子树藏满惊喜` | `Orchards... are wonderful!` 类 | 藏满惊喜 | ❌ 主题反了 | **改英文** 匹配"藏满惊喜"主题 |
| `cactus P8 换成仙人掌长在沙漠里` | `Stars shine in the desert sky` | 长在沙漠里 | ❌ 整句主题反了 | **改英文** `Cactus grows in the desert!` |

### 检测模板(L3 输出前必跑)

```
[ ] 用户给"换中文"时,中文是否与英文主题/语义对位?
    是 → 只改中文(情况 A)
    否 → 默认改英文匹配中文(情况 B,不再反问)
[ ] 是否已经不再问 A/B/C 选哪个了?
    是 → 继续
    否 → 立即停止反问,按情况 B 默认走
```

## ⚠️ 第三十一类陷阱:L4 手部细节铁律(v1.8.0 NEW · 2026-07-24 gardener 实测新增)

### 用户实测原话(gardener 看图后反馈)
> 「**查看了刚刚生成的图片,发现所有图中的人物角色手部细节有残缺(手指数量不对)请你修改提示词**」

### 协议(必须遵循 · L4 输出前默认套用 · 带人物必加)

**触发场景**:L4 生图涉及人物角色(园丁/老师/医生/农民/parent 等职业类,或穿特定服装的小孩等具体人形)→ 必须加 ⚠️ 手部细节铁律段。

### L4 提示词固定话术(必加 · 放在反丑化铁律之前)

```
⚠️ 手部细节铁律(请严格执行,每页人物手部必须遵守):
- 人物每只手必须正好 5 根手指(**拇指 + 食指 + 中指 + 无名指 + 小指,全部存在,全部清晰可辨**)
- **绝不允许 4/6/7/8/9 根或任何畸变指节**
- **绝不允许手部简化为"棒棒糖状球形手"或"连指手套状"**——必须画出真实的五根分离指节
- **绝不允许手指融合或短小齐根**——每根手指应有明确的指身与指尖
- 蜡笔童趣风格下也必须保持"5 根分离指节结构清晰可见",可以简化指甲/关节细节,但五指数量与分离度不能少
- 当人物"握着水壶/铲子/剪刀/工具"时,必须能数出包裹工具柄的 5 根手指(拇指与其他 4 指绕柄呈 5 个独立轮廓)
```

### 每页生图提示词中"手部动作"细化模板

针对职业类绘本常用动作,给出 5 指细化模板:

| 动作 | 5 指细化模板 |
|------|-------------|
| 握工具柄 | "5 根手指——拇指贴柄一侧 + 食指中指无名指小指绕柄另一侧,四指分离可见" |
| 叉腰 | "5 指轮廓清晰可见,拇指在前贴腰 + 其余 4 指并排往后" |
| 扶帽檐 | "5 指完全清晰可见——拇指贴帽边 + 食指中指无名指小指依次分布" |
| 对捏小物件 | "拇指 + 食指呈 V 形对捏之势,其余 3 指自然弯曲" |
| 张开轻抚 | "5 指自然张开呈扇形——拇指向上 + 其余 4 指依次展开" |

### 检测模板(L4 输出前必跑)

```
[ ] L4 是否带人物角色(园丁/老师/医生/parent 等)?
    是 → 必须加 ⚠️ 手部细节铁律段
    否 → 跳过(本铁律不适用于纯动物主角/纯景观)
[ ] 每页人物动作是否用 5 指细化模板描述?
    是 → 继续
    否 → 立即改写具体动作描述
[ ] 是否避免了"棒棒糖状球形手"/"连指手套状"/"手指融合"等陷阱?
    是 → 继续
```

### 与 picturebook-creator v5.2.0 的协同

- v5.2.0 现有"反剪影铁律"(人物非剪影)→ 第三十一类 **升级为"反剪影+反畸变手部"双铁律**
- v5.2.0 现有"默认主角用动物"铁律 → 第三十一类 **例外**:必须画人物的绘本(职业类/特定要求)= 必加手部细节铁律

### 实测触发

- 用户说"手指数量不对" / "手部残缺" / "手部不自然" → 立即应用本铁律
- L4 输出前自检:含人物角色 → 默认应用本铁律(不需要用户主动触发)
