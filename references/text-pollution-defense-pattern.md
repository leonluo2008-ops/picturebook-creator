# 即梦生图文字污染防御模式

## 概述

即梦（Dreamina/Jimeng）生图工具会自发在画面上添加非目标词文字。本文件归集所有已观察到的污染形态、触发条件和修复模板。

**适用范围**：所有 picturebook-creator L4 输出。

## 污染形态分类（按严重度）

### Tier 1 · 常见污染（已多次实测）

| 污染类型 | 实测案例 | 目标词 |
|---------|---------|--------|
| 主题相关标签 | "SIGNALS" / "Service" / "help vehicle" / "EHICLE" | ambulance |
| 主题相关标签 | "XXX" / 随机英文 | student / 职业类 |
| 主题相关标签 | "v=Xxx" / 等式符号 | polar bear |
| 主题相关标签 | 拉丁字符水印 | leopard |

**根因**：即梦对训练数据中常见主题词（救护车/医生/动物）会触发模型自发添加标识语/标签。

### Tier 2 · 字母算式污染（2026-07-18 pelican 实测 · 最严重）

| 污染类型 | 实测案例 | 字符清单 |
|---------|---------|---------|
| 算式数字 | `n=5951` / `m=3959127` | 数学算式 |
| 中文数字算式 | `一九八九一一九` | 中文数字 |
| 分数 | `1/2 一减 二` / `多 1减1` | 分数符号 + 中文减法 |
| 罗马数字 | `v=Xxx` | 罗马字母 |
| 中文字体变形 | `赫尔÷赫尔亚` | 字形拆解错误 |
| 坐标/等式 | `v=Xxx` / `赫尔÷赫尔亚` | 等号 + 坐标 |

**根因**：目标词本身是大写字母组合（pelican/CASTLE/HYACINTH）或字母被多次提到时，模型把"字母"作为视觉元素自由发挥。

**触发条件（满足任一 = 高风险）**：
- 目标词字母数 ≥ 6（如 pelican=7, castle=6, hyacinth=8）
- 目标词全部大写出现在提示词中（如 PELICAN!）
- 提示词里"字母"这个词被多次提及
- 风格是字体主导的（波普艺术/海报风）

## 修复方案（已验证有效）

### 修复模板 1 · 全局设计约定警告（必须用排除式清单）

```text
⚠️ 文字硬控制(严格执行,避免AI自发加文字): 整张图除彩色文字块"[X]"和紧贴其正下方的中文"[Y]"以外,画面中绝对禁止出现任何其他英文字母、英文单词、中文字、数字(0-9)、数字编号、数学符号(分数、加减乘除、等于号)、坐标、几何符号、罗马数字、标点符号(. , ! ? 等)、箭头、日期、时刻、版权符号、水印、签名、AI 模型名、字幕、说明文字、随机噪声字符、方程式。画面是干净的无杂字插画,只有一处文字组合(英文 [X] 在上、中文 [Y] 在下)居中上方。如出现任何其他文字字符视为生成失败,必须重新生成。
```

**关键点**：必须用排除式清单（≥8 类禁用项），不能用"不允许其他文字"这种泛指。

### 修复模板 2 · 每条生图提示词末尾重复

```text
整图除彩色文字块"[X]"和正下方"[Y]"以外绝对禁止出现任何其他英文字母、英文单词、中文字、数字、符号、随机字符。
```

### 修复模板 3 · 退一步方案（终极 fallback）

如果即梦文字控制问题持续无法修复，**先纯生图（无任何文字）**，再后期用画板工具加文字。

提示词改为：
```text
本图不包含任何文字。文字在后期用画板工具添加。
```

## L4 输出前自检清单

```
[ ] 文字硬控制警告已包含排除式清单（≥8 类禁用项）？
[ ] 每条生图提示词末尾都重复了"绝对禁止"声明？
[ ] 目标词本身字母数 ≤ 6？超过 6 字母必须用最强警告
[ ] 目标词全部大写出现次数 ≤ 3？（如 PELICAN!/PELICAN/PELICAN! = 3 次还行，4+ 次必触发）
[ ] 是否触发了 Tier 2 字母算式污染高风险？
```

## 失败重生成信号

如果生图出现以下任一情况，必须重新生成并在提示词中加强警告：

- 画面出现非目标词的英文单词
- 画面出现任何数字、罗马数字、数学符号
- 画面出现算式（n=x / 1/2 / x=）
- 画面出现中文字体变形（汉字结构被拆错）
- 画面出现坐标、几何符号、箭头
