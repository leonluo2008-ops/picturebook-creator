# 项目标准交付 · Codex

## 自动触发

用户要求制作或生图且未限制交付范围时，完成成图验收后自动执行本规范，不另请用户确认打包和上传。仅预览、暂不上传、暂停等明确指令优先。

验收包括：页数齐全，采用最新选定版本，封面布局合格，关键文字拼写正确，角色五官完整、跨页一致，背景无明显异常。质检报告作为辅助；互动页按真实设计设置多主体，避免误判。字母配色允许合理偏差，不因细微差异反复重出。

## 转换与打包

1. 从系列生图工具 `tests/<排产号>-pages/pNN.png` 获取最终页，按真实页码顺序排列；确认页数与定稿一致。联系表、资产、旧版本和日志不进入交付 ZIP。
2. 转为 RGB JPEG。封面 960×1280，内页 1920×1200。内页若为1920×1216，上下各居中裁8像素；其他意外尺寸先检查构图，不静默拉伸。
3. 每张不超过300×1024字节；JPEG质量从90开始按需递减，保留可读性。若到质量40仍超限，不能带着超限文件声称合格，应调整并复核。
4. 按阅读顺序命名 `0.jpg`（封面）、`1.jpg`…；使用 ZIP DEFLATED，文件名 `<排产号>.zip`。
5. 本项目保存目录：`绘本创作/作品/<作品目录>/交付/`。打包后重新打开ZIP，验证成员数量、顺序、格式、尺寸、单图大小与文件可读性。

## Notion 回传与回读

- 使用已授权凭据在进程内加载，不打印、复制或提交密钥；不修改 Hermes 配置。
- 精确定位台账行并核对排产号、核心词与 page_id。查询必须处理分页，不能仅扫首100条；已知 page_id 也须核对属性。
- 通过 File Upload API 上传ZIP，确认上传状态为 uploaded，再挂入页面的「交付文件」files属性，成功后状态更新为「已生图」。
- 保留已有附件。相同内容已交付时跳过重复上传；同名但内容有更新时使用带版本或时间的文件名追加，不能仅凭同名就把旧包认作新包，也不覆盖整列丢掉旧附件。
- 独立 GET 页面，核对附件名称、有效文件项、状态及正确台账行。发生中断先回读现状，只补未完成步骤，避免重复上传。
- 失败时保留本地ZIP并说明失败环节，不宣称已交付、不提前推进状态。
