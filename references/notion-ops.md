# 台账与资产图库运维（L5 · 改写 · 存量重整）

> 创作口径不在这里，这里只管**怎么读写 Notion、怎么判断写对了没有**。
> 依据：读走 MCP/脚本兜底、**台账写与改写一律脚本一条命令**〔裁定 R15〕；写操作必须所有者同意〔裁定 R5〕；改写模式〔裁定 R4〕；存量回填后置〔裁定 R10〕。

## §1 访问路径：读走 MCP，台账写与改写走脚本〔裁定 R15〕

装好 `dsh-notion-oauth-ui`（OAuth，官方 Notion MCP）后，**所有 Notion 读（查询/fetch）优先走 `mcp__notion__*` 工具**。**台账的写与改写不在此列：一律 `scripts/notion_archive.py` 一条命令**（`--rewrite/--status/--note/--gloss`），不手拼 MCP 写参数〔裁定 R15〕——现场拼参数已实测两次翻车。MCP 写接口只作脚本失效时的人工兜底。

**判定**：读 → 有 `mcp__notion__*` 一律用 MCP；写/改写 → 永远脚本。

**新接口的正确入口**

- 先 `fetch` 数据库 URL → 返回体里带 `<data-source url="collection://…">`；**查询必须用 data_source URL**，不要拿数据库 id 去 query。
- `query_data_sources` 三种模式：`rows`（保留富文本/链接，**改属性前必用这个模式读**）、`sql`（聚合与筛选快，但不带 mention 与格式）、`view`（跑某个已保存视图的筛选）。
- **禁止靠视图取数**：台账 Default view 自带筛选（只含 `备选 / 已筛查 / 待生图 / 已生图`），按视图取书会漏掉 `已制作 / 修改中 / 弃用`。要全库必须显式查询。〔裁定〕
- 「词型」是 **rich_text 属性，不是 select**——按 select 写必 400。
- `绘本资产图库` 的 `data_sources` 为空，只能走旧式 `/v1/databases/{id}/query`；台账走新 data_source 链路。**两条链路别混用。**

**脚本兜底的定位三段式**（脚本已内置；手工兜底时照此执行）

```
中控台页 page_id → 正文 child_database(台账库) db_id
  → GET /v1/databases/{db_id} → data_sources[0].id
    → POST /v1/data_sources/{data_source_id}/query   ← 唯一可 query 的入口
```

- **child_database id ≠ data_source_id**：拿 db_id 直接 query 必报 400 `invalid_request_url`。
- 默认 data_source 失效时脚本自动沿线重新发现；换工作区用 `NOTION_CONTROL_PAGE_ID` / `NOTION_LEDGER_DB_ID` / `NOTION_DATA_SOURCE_ID` 覆盖。
- **复用 `api()` 只传 path**：签名 `api(path, method="GET", body=None)`。写成 `api("GET", path)` 会把方法名当路径、拼出 `https://api.notion.comGET`，报 `URLError [Errno 2]` 且堆栈落在 SSL 握手——表象像断网，实际是参数错位；判据是打印 `req.full_url` 看主机名是否完整。
- **读页面子块走 `GET /v1/blocks/{page_id}/children`**；`GET /v1/pages/{id}/children` 报 400。

## §2 写入边界与状态流转

- 读（search / fetch / query）：可以直接做。
- **写（建页、建行、改状态、改备注、删块、上传附件）：必须先得到用户明确同意**，不得自行推进状态，不得「顺手」补档。〔裁定 R5〕
- 未验证能力不许宣称可用：MCP 上传二进制（ZIP 交付包）**本 skill 尚未验证**；交付仍以 `scripts/notion_archive.py` 的已验证路径为准。

**状态机（8 项）**：`已筛查 / 备选 / 待制作 / 待生图 / 已制作 / 已生图 / 修改中 / 弃用`（以当次 fetch 的 schema 为准，选项可能增减）。

| 状态 | 含义 | 谁能推进 / 何时 |
|---|---|---|
| 备选 | 台账已有、未筛查 | 筛查环节决定 |
| 已筛查 | 选题过筛、没动笔 | 派到即开全新 L1→L5 |
| 待制作 | 已排进制作计划、未开工 | 开工即走 L1→L5 |
| 待生图 | L4 已确认并归档，等出图 | **agent 自动**：归档 + 回读校验通过后 |
| 已生图 | 图已出，**且交付包已挂「交付文件」** | **agent 自动**：交付回读通过后 |
| 修改中 | 审核/甲方打回，待改 | 收到意见即置；改完**仍留此态**等复审 |
| 弃用 | 终态 | 仅所有者决定 |
| 已制作 | 历史状态：已有产出（未必生图/交付） | 不再主动写入；先查「交付文件」列判断实际进度 |

**agent 只允许自动推进两个动作**：归档完成 → `待生图`；交付回读通过 → `已生图`。其余流转归排产流水线与复审。〔裁定〕

- **`已制作` ≠ 已交付**：判断「这本书交付过没有」看「交付文件」列，不看状态。
- **按状态取书**：过滤值必须来自库里的真实 options，不照抄用户口头的状态名（用户说「必选」实为「备选」时，按语义最近的真实 option 过滤并明说，不拿「库里没这个状态」当结论回给用户）。
- **按排产号开工先核状态**：排产号是 title 列，按核心词 rich_text 过滤查不到——全量翻页后按排产号匹配。号不存在就如实回报并给最接近的现存号，禁止拿别的行顶替。
- **排产号以台账实时 query 为准**，不按会话记忆宣告。


**状态「待审查」（2026-11-21 新增）**：用于**存量回填/重整后交所有者过目**。与流水线状态的区别是：它不是 agent 自动推进的节点，而是「东西已经写进页面、等所有者本人看」的停顿态。置为 `待审查` 后，`notion_verify.py` 的「归档后状态应为 `待生图`」断言会报一条 ✗ —— 这是预期差异，不是归档失败。
## §3 L5 归档：一条命令

```bash
# 1) 先定位行（只读，确认核心词命中哪一行，拿到排产号/行 page_id）
python scripts/notion_archive.py --word day --locate

# 2) 归档正文（heading + 选定标题中英两行 / 简介 + 旁白表 + L4 全文 + 回读校验）
#    --gloss 必带：本书已确认中文释义（与机检同一来源——台账「中文释义」列 / L1 需求确认表），
#    脚本用它做归档前认读释义硬校验；缺参 EXIT=1 拒归档
python scripts/notion_archive.py --word day \
    --title 'Here We Go, "day"' --title-cn '一起学 day' \
    --brief '选定简介全文' --gloss '地板' \
    --narration /tmp/narration.md --l4 /tmp/l4.md \
    --asset '蜜桃猫-二创' --date 2026-10-24

# 3) 只想看会写什么（不发任何写请求）
... 同上 ... --dry-run
```

| 参数 | 说明 |
|---|---|
| `--word` | **必填**，台账「核心词」列精确匹配 |
| `--title` / `--title-cn` / `--brief` | 英文标题 / 中文标题 / 选定简介。「选定标题」段固定两行：`英文标题:…` + `中文标题:…`——生图提示词只提取英文标题做封面主文字 |
| `--narration` | 旁白文件：markdown 表 `| 页码 | 英文 | 中文 |`（表头/分隔行自动跳过）或 JSON。**第四列「领读」为工作表字段，归档不入台账**——脚本只取前三列（`parse_narration` 取 `cells[0..2]`，台账固定三列表头），领读提示留在工作稿里供带读人用 |
| `--l4` | L4 生图提示词纯文本全文 |
| `--gloss` | **完整归档必填**（2026-11-26）：本书已确认中文释义，认读释义硬闸的判据输入——**与第 1 道机检传同一个值、取自同一出处**（台账「中文释义」列 / L1 需求确认表），不许两处取值不一致；材料冲突时停下向所有者报告，不许挑一个让检查通过 |
| `--date` | 归档日期，默认今天 |
| `--page-id` | 直接指定台账行，跳过按核心词查行（多行命中时用） |
| `--attr-title` / `--attr-brief` | 可选属性回填，默认关闭（直接回填正文即可） |
| `--word-type` | 新建行时写入「词型」 |
| `--sched-no` | 新建行时指定排产号，默认取全库最大 B###+1 |
| `--no-create` | 禁用自动建行 |
| `--force` | 该行已有创作产出段时仍**追加**一段（默认拦截；要覆盖不是用它，见 §6） |
| `--locate` / `--dry-run` | 只读定位（并预告会不会建行）/ 干跑（不受重复归档拦截，只预览） |
| `--asset` | 可多次：在「L4 生图提示词」标题下、代码块**之前**追加独立资产提及块，前导文字「参考图[定位]-点链接查看参考图：」。**链接绝不注进代码块**——整块复制提示词时会拖进 URL |

**铁律**：按核心词精确匹配**先查行**——已有则该行复用，**绝不重复建行**；没有才自动建行（排产号取全库最大 B###+1，状态列留空）。命中多行 → 停下，用 `--page-id` 指定，禁止猜。**完整归档必须传 `--gloss <释义>`**（本书已确认中文释义）：归档前脚本会用它在本地重跑「认读释义门禁」（rules.md §六），未过 = 拒绝归档；确实无释义的存量补档显式 `--allow-no-gloss` 放行（打印 WARN）。〔2026-11-26 裁定〕

**脚本固定写入顺序**（最后回读校验，缺失项 exit 1）：

1. `heading_2`：`📚 创作产出(YYYY-MM-DD 归档)`
2. `paragraph`：选定标题（两行：英文标题/中文标题）/ 选定简介
3. `heading_3`：双语旁白 → `table` 块（3 列，首行表头）
4. `heading_3`：L4 生图提示词 → **一个** `code` 块；超过 1900 字时按行边界切成多条 `rich_text` 放进**同一个** block
5. GET `/v1/pages/{page_id}/markdown` 回读，核对 heading / 旁白首行 / L4 场景锚点 / 核心词

> **为什么是一个 block 而不是多个**：Notion 的 2000 字符上限作用于**单条 rich_text**，不是整个 block；一个 block 的 rich_text 数组最多 100 条。按「每个 chunk 建一个 code block」写，3000 字以上的 L4 会在页面上被劈成两截。

**交接界面**：用户确认 L4 → 静默归档 → 状态置「待生图」→ 只回一句「已归档 Notion ✓（排产号/行）+ 状态已改待生图」，不搬运长文到聊天。存量重整批量完成后回一张 TL;DR 表，不逐本搬运长文。

**L4 审阅工作流（2026-11-23 所有者改定，替代上述「先确认再归档」）**：聊天里**不贴 L4 长文、不报文件路径**——所有者不看这些。改为：L4 过完三道门禁 → **直接归档 Notion（`notion_archive.py` 一条命令）但状态留空不推进**，只回一句「已归档 Notion ✓（排产号），请在 Notion 页面查看」。所有者在 Notion 页面上看内容、提改动；agent 改稿重归档（内容改动走 `--rewrite`，状态始终不推）。**只有所有者亲口说「确认/没问题/可以生图」后，才用 `--status 待生图` 推进状态**。旧的「agent 自动推 待生图」只适用于所有者已确认过内容的场景。〔裁定·2026-11-23〕

### 归档页正文骨架（不许手拼）

归档产出的页面正文应有如下形态：

````markdown
## 📚 创作产出（YYYY-MM-DD 归档）

选定标题：<br />英文标题：<英文标题><br />中文标题：<中文标题>

选定简介：<选定简介全文>

### 双语旁白

| 页码 | 英文 | 中文 |
| --- | --- | --- |
| 封面 | ... | ... |
| P1 | ... | ... |

### L4 生图提示词

```txt
（四段结构的整块提示词）
```
````

- 这四块（H2 带全角括号与归档日期 / 选定标题两行用 `<br />` 换行 / `### 双语旁白` 三列表 / `### L4 生图提示词` 一个 code 块）**由 `scripts/notion_archive.py` 自动产出**，人不手拼。
- **2026-11-23 实测教训**：用 `mcp__notion__notion-update-page` 的 `replace_content` 手写正文，属性改对了但**正文只剩纯文本**——H2 标题、旁白表格、`入画英文`/`页序` 字段全丢，页面结构不可用。所以「MCP 兜底」只能用于脚本失效，且必须按上面骨架逐块补齐后回读（heading / 表格 / code 块逐项核对，缺一项即不可交付）。

## §4 归档后独立回读（不信脚本自报）

脚本自报「回读校验通过」只是它自己的口径，交付前用独立脚本再 GET 一次：

```bash
python scripts/notion_verify.py --word <核心词>                # 页数默认 9（封面+8内页）
python scripts/notion_verify.py --word <核心词> --pages 10     # 页数不同时给 --pages
python scripts/notion_verify.py --page-id <page_id> --pages 9  # 多行命中/已知行 id 时
```

它不 import 归档脚本（定位走子进程 `--locate`，校验用自己那份 HTTP 代码），EXIT=1 即有不符项。

| 核对项 | 端点 / 判断 |
|---|---|
| 状态 / 排产号 / 核心词 | `GET /v1/pages/{id}` 读 properties |
| 段落骨架 | `GET /v1/pages/{id}/markdown`；heading 实际是全角括号「📚 创作产出（…）」——按「创作产出」子串找，拿半角括号拼串会误报缺失 |
| 旁白表完整 | 回读里旁白导出成 HTML `<table>`，数 `|` 恒为 0（正常）；按 `<tr` 计数 = 表头 + 页数 |
| L4 结构 | `比例: 3:4` ×1、`比例: 16:9` ×内页数、每页各有「场景锚点」或「场景一致性」标签与一条构图要求、三反引号围栏 = 2 |
| 重复归档 | 上面这组计数**整体翻倍**（围栏 4、16:9 是内页数×2、场景锚点是页数×2）= 页面上躺着两个逐字相同的 code 块——按 §6「先删后归」清掉重写，别在旧块上逐句修补 |
| 选定标题栏 | `英文标题:` 值里不得混中文，也不得以 `, "核心词"` 收尾（`--title` 塞了整串而 `--title-cn` 漏传就会长成这样）。核对办法：`--title` 只放英文、`--title-cn` 单独传，回读时用 `[\u4e00-\u9fff]` 与「`, "词"` 结尾两条断言过一遍 |

数字对不上先归一化渲染工件（`<br>`、转义引号）再下结论，别急着重写正文。

## §5 改写模式（审核意见退回后改已交付的书）〔裁定 R4〕

> **与「存量重整」的区别**：存量重整 = 旧规范产出的旧档按新规范补缺口；**改写模式 = 本书已按当前规范交付过，甲方/审核提意见要求修改**。两者入口相同（先定位台账行），但触发条件、状态与验收不同，不得互相替代。

**触发**：台账状态 = `修改中`，或用户转述审核意见。

**第一步：把意见归层，只改被点到的那一层，其余一律不动**

| 意见指向 | 改哪里 | 改法 |
|---|---|---|
| 标题 / 简介 | 台账正文的标题块、简介段 | 只重出被点到的那一条，其余照原文；重出后逐条对回旁白真实页面 |
| 旁白（中文列） | 旁白表对应行 + L4 当页「旁白:」行 | 单行 `PATCH /v1/blocks/{table_row块id}`；L4 旁白行是「英文 / 中文」形态，中文改动**必须同步 L4** 并重跑 `grammar_check.py` |
| 旁白（英文列） | 旁白表行 + L4 当页「旁白:」行 | 两处同步；改完重跑 `grammar_check.py` 与 `l4_case_check.py` |
| L4 提示词（画面/动作/构图） | L4 code 块对应页 | 单块端点取全文 → 字符串替换（前后 `assert count==1`）→ 按 1900 切段、交替 bold 防合并 → PATCH 回同一 code 块 |
| 成图本身（画面质量） | 不出文本 | 只输出「需重生图的页」清单给用户，不得谎称已改好 |

**第二步：改写后的三道门（缺一不过）**：`grammar_check.py` → `l4_case_check.py` → `l4_presence_check.py --expect-pages <页数>`，全 EXIT=0。

**第三步：状态与回读**

- 改完**仍留 `修改中`**，等复审；不自行推 `待生图`。
- 备注整段覆盖为本轮改动摘要（不追加、不拼接）。
- 回读只针对本轮改动项及其相邻项，不重跑全量；但只要动了英文列或 L4，第二步三道门必须全绿。

**终止**：放弃一本 → 状态置 `弃用` + 备注写终止原因；不删页面，排产号保留。
**只改文字**：简介与旁白中文列都不进画面，改它们不需要重做已生成的图；改了封面英文标题/画面文字形态才涉及重做。

## §6 存量重整（旧档按新规范覆盖）

> 用户给清单 → 提取核心词 → **串行逐本**处理，一本归档校验通过再开下一本，不要并发。**存量一律不回填**〔裁定 R10〕，只有这本书被重整或改写模式动到时才顺带补齐。
>
> **存量旧档默认不体检**〔裁定·2026-11-23〕：2026-11-23 之前归档的书，除非所有者点名要查，否则**默认不跑任何结构复核、不主动报缺段缺项、不提议回填**。需要复核旧书时才用 `l4_structure_check.py --legacy`；没被点名的旧书一律当它没被问过。

**每本固定五步**

1. `--word <词> --locate` 拿行 page_id（清单批量时先全部定位一遍，确认每本都有既有行、拿到页 id，再动笔）。
2. GET `/v1/pages/{page_id}/markdown` 拉旧档存盘，从中**逐字提取**选定标题、选定简介、旁白表。仅重整 L4 时，保留原有标题、简介、旁白、角色与场景锚点；用户确认同时修订旁白时，先定新版旁白表再同步 L4 对应页。
3. 按当前规范给旧 L4 补缺口，产出新 L4 纯文本文件（整本一个代码块的内容，不含围栏）。
4. **真覆盖＝先删后归**：`--force` 是**追加**不是覆盖（照它做会把新旧两段并排留在页面上）。先清场删旧块（口径见下一条），再走**正常归档**（不加 `--force`；标题/简介用第 2 步提取的原文传回，旁白存 markdown 表文件传 `--narration`）。
   - 清场按**内容白名单**删块，不按 heading 定位：GET 页面子块，只保留筛查三行（`核心词义` / `主题关联` / `原有核心词`），其余一律 DELETE，删完回读并逐条打印剩余块，确认只剩三行再归档。
5. 回读校验：逐本拉回 markdown 按项计数（同 §4），另人工核对全部旁白与入画词是否按整词呈现。批量改动后把备注整段覆盖成本轮摘要，并把「待重生图的页」告诉用户。

**轻量变体**（只动个别页，不删块重归）：① 旁白表单行 `PATCH /v1/blocks/{table_row块id}` 直改；② L4 code 块用单块端点取全文 → 字符串替换目标段（前后 `assert count==1`）→ 按 1900 切段交替 bold 后 PATCH 回同一 code 块；③ 回读只核「新句在位 + 被剔词/旧话术残留为 0」两项。

**剔一个词要连带清三处**：① 格数措辞——它同时出现在提示词正文与**「构图要求」句**里，只改正文不改构图要求，安全区口径就自相矛盾；② 该词的配图道具——道具清单里为它准备的那件东西跟着下线；③ 互动页/其他页若曾用该词一并核。清完 grep 三样：被剔词、该词的配图道具、「三个」类计数措辞。

**旧档常见缺口清单（逐条对）**

- 封面条只写核心词或裸「封面」，没有 `封面(中文标题 / 英文标题)` 条目；封面提示词里出现中文标题字样。
- 词族页保留时先核词的入选条件；改词同步改双语旁白和 L4，旧稿单独呈现的词尾与发音口令一并清理。
- 整本没有「构图要求」句式——每页末尾按当页主体补齐，高危部位点名。
- `旁白:` 行带 `P1 …` 页码前缀，或 `页面类型:` 写成「P1 语境重复页」——去掉前缀。
- 互动练习页只有装饰画面，没有找找看任务与干扰物设计。
- 柔和水彩类风格写了「留白自然」类措辞——删掉，改成「整幅画面被场景色彩填满，背景是具体场景环境，不是留白纸面」。
- 角色动作超出肢体能力——按角色可行性审查改写动作。
- 画面字母全大写与当页旁白不一致——按 `l4-spec.md` §5 逐页改回。

## §7 资产图库（参考图存放地）

参考图主存放地＝**Eagle 素材库**（所有者维护，主库）；Notion「绘本资产图库」只记链接、复用说明与关联排产，**不重复上传原件**。Eagle 里按项目建文件夹（如 `儿童绘本/B615 pen-小刺猬与小兔`）。〔2026-11-23 所有者裁定〕

| 字段 | 用途 |
|---|---|
| 资产名称 | 精确匹配键（`--name`），定名用短名 |
| 参考图片 | files 列表，可多图 |
| 资产类型 | select：**角色 / 风格参考**（库内实际选项，旧文档写的「场景 / 物件」不存在） |
| 使用定位 | select：**灵感参考 / 制作基准**（制作基准＝L4 严格以图像1为准；灵感参考＝提取风格再创作）。**取值以库 schema 为准** |
| 来源链接 | 原始出处 url |
| 复用说明 | 一句话复用纪律（如「尾巴要改，避免版权」——L4 提示词必须执行） |
| 关联排产 | relation → 排产台账行，反查「这个角色用过在哪几本」 |

```bash
python scripts/asset_ref.py --list                                  # 全部资产
python scripts/asset_ref.py --name 跳跳虎 --download C:/tmp/ref.png  # 精确定位 + 顺手下载
python scripts/asset_ref.py --name 跳跳虎 --link-word bike            # 归档联动（幂等）
```

- 资产定位**多行命中即停**，报错让用户指定，禁止猜。
- **下载地址是临时签名 URL 且只支持 GET**（HEAD 直接 403）——要图就现场下载。
- **改名即改匹配键**，脚本没有 rename，直接 PATCH 标题；relation 挂在 page id 上，改名不影响已挂的排产行，回读 `--list` 确认「关联排产」仍在。发现错别字**先改名再归档/挂链**。
- L1 用户丢参考图时：先查图库有没有同类资产，有 → 复用并问是否沿用其「复用说明」；无 → agent 代建行 + 传图入库，不让用户手工建行（API 全流程：建行 → 建 `file_upload`（content_type 必须与文件实际格式一致）→ `send` 端点收 multipart `file` 字段 → attach 到 `参考图片` → `--name` 回读验证）。
- L5 归档后用 `--link-word <核心词>` 把每条用到的资产挂到台账行，双向可溯。

## §8 本地产物清理（Notion 是正式存档，本地稿件为生产/验证/续跑材料）

> 唯一正本条款，首次归档收尾与修改重归档收尾**都引用本节**；批量任务另加批次条款。

- **Notion 是绘本创作内容的正式存档**；本地 `projects/<排产号>/` 稿件、L4、导出件与批次中间文件的存在理由只有三个：生产、验证、续跑。三个理由都消失的文件即可清理。
- **单本归档/重归档收尾**：正式写入完成 + `notion_verify.py` 独立回读确认 Notion 内容完整且与本地定稿一致**之后**，才清理该书已交付的本地临时产物（如重写前的旧快照、临时导出件、一次性探针输出）。`projects/<排产号>/` 内**正式定稿文件保留**（后续生图迭代、成图验收、回写都要用）。
- **批次收尾**：批次对账完成、确认续跑与待处理书仍有所需材料后，统一清理已完成书的本地产物；**失败、待回读、待重试或仍被后续交付使用的文件保留**到对应工作完成。
- **每次任务收尾顺带检查历史残留**：以明确的项目路径和文件用途划定范围，**先列出待清理项 + 每项的线上核验依据（Notion 归档段/回读通过记录），再执行**。按用途保留：Skill 与脚本、正式测试夹具（门禁正负例）、用户尚未提交的改动，一律不清。
- **Git 纪律**：生产稿已被 Git 跟踪的，核对依赖后通过正常提交移出当前工作树（保留 Git 历史，可随时回溯）；未跟踪的临时产物直接删除。改动纪律仍按全局约定——不造 `.bak`。
- 清理后**必须读回验证**：列出剩余文件清单 + 关键保留文件仍在，作为收尾证据。

## §9 工具层坑（按报错定位，别盲试）

- `PATCH /v1/pages/{id}/markdown` 已不可用（报 `body.type should be defined`）→ 一律用 `PATCH /v1/blocks/{page_id}/children`。
- `table` 块：**不要** `cells` 字段；必须带 `children:[{type:"table_row",table_row:{cells:[[rich_text数组],[…],[…]]}}]`，单元格是 rich_text 数组直接放，外面不再包一层；`has_column_header: true`。
- **改表格单行**：`PATCH /v1/blocks/{table_row块id}`，body 为 `{table_row:{"cells":[[rt],[rt],[rt]]}}`——cells 是「每列一个数组」，数组个数必须等于表列数，没改的列也要原样带上。三种层级写错各报不同的 400：`cells[0] should be an array`＝少一层（把 rt 对象当成了 cell）；`cells[0][0] should be an object`＝多一层（cell 里又套了数组）；`Number of cells in table row must match the table width`＝数组个数或层级错。
- `rich_text.content` 单条上限 2000 字符 → 按 1900 按行切段；**切出来的是同一 code 块里的多条 rich_text**。
- **PATCH code 块多条 rich_text 必须交替加注防合并**：相邻 rich_text 的 annotations 完全相同时 Notion 会自动合并成一条——回读变回超 2000 的一条、再 PATCH 就报 400。切段后给各段交替 `bold: true/false`（或任一项 annotation 差异）。验证 code 块真实内容/条数必须用单块端点 `GET /v1/blocks/{id}`——children 端点返回的 rich_text 有显示截断。
- **code 块切段必须保段尾换行**：相邻 rich_text 段会被无条件拼接——段尾不带换行，下一段首行会直接粘进上一段末行。切段后逐段断言段尾是换行（末段除外）；PATCH 后用单块端点回读，数「非换行紧贴的四字段标记」= 0。
- **字段挤在同一行不是 PATCH 造的**：旧 L4 可能本身就写着「…better!比例: 16:9页面类型: …」，整块替换会原样把这个缺陷传回去。改这类块时按行拆开再回写：把每个 `比例: 16:9`、`页面类型: `、`生图提示词: ` 挪到行首，并把连续三个以上换行收敛成两个；在回读文本上逐条检查「这三个标记前一字符是不是换行」。
- 台账库需已 Connect 到 integration，否则 404 `object_not_found`。
- 台账超 100 行时 query 必须翻页（`has_more`/`next_cursor`）；按核心词查不到行，先翻完全部页再下「无此行」结论。
- **`--dry-run` 必须零写入**：任何写调用都要放在 dry-run 出口之后——干跑污染生产台账比不跑更糟。
- **会写台账的脚本后面不要接 `| head` / `| tail`**：管道被提前关闭会让脚本里的 `print` 抛 `OSError: [Errno 22]`，循环当场中断，删除只做了一半而退出码报的是管道最后一段的 0。
- **正文归档成功、状态没推进时只补状态，绝不重跑归档**：`advance_status()` 只捕获 `SystemExit`，网络抖一下会把堆栈打出来、整支脚本 EXIT=1，看着像归档失败，其实块已写入、回读已过；重跑会再写一套块（新旧两段并排）。判定：`notion_verify.py` 全过 + 页面块数正常 → 只是状态没改，用带重试的 `PATCH /v1/pages/{page_id}` 补状态再独立回读。
- **对话里定稿的句子必须回写文件再归档**：用户在聊天里点头的改法不会自动落到 `narration_*.md` / `l4_*.md`。归档前把定稿句与原文件逐字比对（`assert count==1` 后替换），不一致先改文件、重跑门禁到 EXIT=0 再归档。
- **改归档/资产脚本后先离线 mock 再碰真实台账**：把模块级 `api`（asset_ref 则是 `_req`）替换成假函数，断言 `--dry-run` 写调用为 0、真跑时建行调用仍发生。真实环境首次验证也先用不存在的探针词跑 dry-run 并回查行数=0。
- **批量写一律带重试**：把 `api()` 包成 3–5 次重试、退避 1.5s×n；瞬时 SSL/URLError 在这条链路上是常态。
- **备注整段覆盖，不追加、不拼接**〔裁定〕：一轮改动只留一条备注写「本轮改了什么」，直接覆盖上一轮。要区分轮次就把轮次写进句子（「甲方打回｜P6/P7 对调、P8 改猜一猜」），不靠叠加历史段落。
- 回读时旁白表是 HTML 形态（`<table><tr><td>` 三列），按 `<td>` 正则提取，别按 `|` 解析；换行导出为 `<br>`、引号转义为 `\"`——精确字符串匹配误报「内容缺失」时先归一化这些渲染工件。
- **批量改行/归档别在旧块上逐句修补**：残留断言要落到位置（`assert "<新封面旁白行>" in 全文`、`assert "<旧英文标题>" not in 全文`），整篇 `assert "旧词" not in 全文` 会误报——旧词可能合法留在场景描述里。
