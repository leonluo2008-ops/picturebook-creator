# 执行者分工与委派（R14 · R17 · 2026-11-22/24）

> 主模型可能文笔强但工具弱（会拼错 MCP 参数、漏填委派参数、把「没写成」报成「已完成」）。
> 本文件回答一个问题：**每件事由谁执行、委派怎么派、派完怎么核对**。
> 裁定依据：R14（三类任务强制分工）、R15（台账写入走脚本一条命令）；模型坐标见 `docs/项目适配包.md` §8。

## §0 执行者与「弱工具」判定（外部静态条件，不许自评）

| 执行者 | 承担 | 判定来源 |
|---|---|---|
| **主模型** | 编排、对话、**跑一条命令级的本地脚本**；不代笔创作 | 会话主模型 |
| **创作子代理（创作槽）** | **创作类**：L1 创作输入（义项/立意线索/角色与风格提案）、L2 理解推进结构与页结构起草、L3 标题/旁白/简介起草与改稿、以及一切面向孩子的文案 | 所有者指定的创作模型（见 §0.1） |
| **子代理（重活槽）** | B 类：方案 / 决策分析 / 审计；**归档后的独立回读核对** | 适配包 §8 `heavy_model` |
| **子代理（轻活槽）** | C 类：L4 整本装配 + 五道门禁连跑；审计第二路 | 适配包 §8 `light_model` |
| **脚本** | 所有台账写入（归档/改写/状态/备注/释义）；门禁、结构核对、格式转换等机械检查 | `scripts/notion_archive.py` 等 |

**按弱工具走的判定是静态的**：会话主模型 = 适配包 §8 标注「创作型/工具弱」的模型（当前 = `gemma4:31b`）→ 本会话全程按 §1 委派。**不因为「这次没出错」就升级为主模型自干**（自评判定无效——审计 B7：被判定者不能判定自己）。

## §0.1 创作槽协议（2026-11-24 所有者裁定）〔R17〕

**所有者原话**：「创作写作文学类的任务应该使用伽马4的模型……在每一次执行任务前初始化时，需向用户询问并由用户指定使用什么创作模型，指定过后就默认使用。每次执行创作任务时，都使用子代理的方式调用对应模型去执行，包括刚开始的部分架构设定、文稿创作这一类的任务，都由它去执行。后续的机械检查、门禁这一系列任务就可以用其他模型，因为创作类的模型是有特定性的。」

1. **初始化必问**：每本书（或每次创作会话）动笔前，先问所有者「本次创作用哪个模型？」，给出默认值（上一次指定值）；所有者没指定新的，就用默认继续。
2. **记忆位置**：`~/.dsh/picturebook-creator.json`，形如 `{"creative_model": {"provider": "ollama-cloud", "model": "gemma4:31b"}, "specified_at": "YYYY-MM-DD"}`。指定后立即更新；文件不存在或与上次冲突时必须显式问，不许猜。
3. **创作类定义**：L1 创作输入（义项/立意线索/角色与风格提案）、L2 理解推进结构与页结构起草、L3 标题/旁白/简介起草与所有改稿——凡产出面向孩子的文字与故事结构，都走创作子代理。主模型只做：转述任务书、把门禁输出带回给所有者、按所有者裁定改。
4. **机械类除外**：门禁命令、脚本、台账写入、结构核对、格式转换、台账字段核对等机械任务，不用创作模型（用主模型或轻活槽即可）。
5. **委派纪律同前**：provider/model 分开传；委派后必跑 `python tools/model_probe.py --newest 3 --expect <provider> <model>`，EXIT≠0 或 SKIP 一律视为路由未生效；产物必须独立读回，子代理自述不算证据。
6. **现行默认**：`ollama-cloud / gemma4:31b`（2026-11-24 所有者指定）。
7. **每个创作任务书必须含「自复读清理」环节**〔2026-11-24 所有者裁定，原话「做完之后还要要求模型读一遍，移除那些拗口的东西和不符合小孩子讲故事语境的东西，这非常重要」〕：子代理交稿前必须出声（按发音）通读一遍，删改——拗口/拗口令式句子、书面词、大人腔、广告腔、抽象评价；判据 = 5 岁孩子听一遍能跟上、像在跟他说话。子代理报告必须附「自读清理清单」（改了哪些词句、为何改）；主模型收稿后再整体朗读一遍复核，不过不收。

## §1 三条强制分工（所有者裁定，不可条件化）

| 类 | 任务 | 执行者 | 说明 |
|---|---|---|---|
| **A** | **台账写入** | 主模型直接跑 `notion_archive.py` 一条命令 | 脚本是确定性调用，不套子代理（审计 B7：多一层 LLM 判断只会增加失败面）；**写完的独立回读核对委派给重活槽子代理**（执行者与核对者分离） |
| **B** | **方案 / 决策分析 / 审计** | 子代理（重活槽；第二路轻活槽） | 判断力密集；主模型只汇总结论 |
| **C** | **L4 整本装配 + 五道门禁连跑** | 子代理（轻活槽） | 长链路、多工具调用，弱工具主模型最容易中途错参 |

不在清单上的（日常查台账、跑门禁单条命令）主模型自己干；**创作稿不再由主模型执笔，一律走 §0.1 创作槽**。**L4 逐页生图提示词 = 轻活槽**（2026-11-24 所有者裁定：L4 属机械装配+门禁，不属创作类）。

## §2 委派任务书模板（参数逐字字面量）

```
subagent(
  description="一句话说清交付物（必填，缺了工具直接拒绝）",
  name="短横线小写名",
  provider="ollama-cloud",          # provider id，来自适配包 §8 槽位
  model="deepseek-v4.1-flash:1017", # 只写 model id，不带 provider/ 前缀
  prompt="GOAL/CONTEXT/FILES/CONSTRAINTS/VERIFY/REPORT 六要素；任务书里每个值写字面量"
)
```

- `provider` 与 `model` **分开写**，`model` 带 `provider/` 前缀会静默回退主模型（2026-10-10 实证）。
- 报告首行要求子代理写 `MODEL: <provider>/<model>`——**这只是声明，不作证据**（实测发生过「实跑 gemma4 却回报已用 deepseek」）。
- **创作类任务书必带「三件输入」**〔2026-11-24 创作方法更新〕：GOAL 或 CONTEXT 里必须先给子代理——① **本书目标义项**（逐字，如「手帕：擦汗/捂鼻/递给哭了的伙伴时用」）；② **已确认材料清单**（L1 已确认的立意线索、年龄、画风、主角；L2 已确认的页序结构；L3 已定稿的旁白表——按本步实际进度给）；③ **本步要做的具体判断**（一句话，如「判断全书是连续推进还是情境并列，据此选手法」）。缺任何一件，子代理应回报暂停而不是自行脑补。
- **创作类任务书追加三项**：① CONSTRAINTS 里写明「交付前先出声通读全文，删除拗口/书面/成人腔表达」；② REPORT 里必须附「自读清理清单」（改了哪些词句、为什么）；③ **范文附录必带**（2026-11-24 新增，触发事件 B708）：涉及简介/旁白起草的任务书，必须把 3–5 条已入选简介**原文全文**贴进任务书（默认取 B714/B715/B716/B717/B680/B681 的选定简介，随台账推进滚动更新为最近定稿；简介方法论详见 `rules.md` §2「创作方法」），并附一条被否简介作反例；范文先过主模型复核三查（flow.md §4）确认无病灶才可入附录——范文自带病灶会反向校准。缺任一项 = 任务书不合格，主模型应退回重写。

## §3 委派后必做两件事（缺一不算完成）

1. **路由核对走一条命令**：
   `python tools/model_probe.py --newest 3 --expect "<provider>" "<model>"`
   它从会话档读 `agentProvider/agentModel`（真值），EXIT=0 才算路由生效；本机没有 `zstandard` 库时打印 SKIP——**SKIP ≠ 通过**，此时明示「路由未核」。
2. **产物独立读回**：文件用 read、台账用 MCP fetch 或 `--locate`、命令看退出码。子代理「成功」自述不算证据；外部副作用必须亲自复核句柄（page_id / 文件路径 / 哈希）。

路由不符（probe 命中但模型 ≠ 期望）→ 当轮登记「路由未生效」，产物仍按读回判定，不当作废。

## §4 降级纪律

没有 `subagent` 工具的宿主（云端等）→ **停下该操作并告知所有者**，不由主模型自行降级接手（审计 B3：强制委派不许被「工具不在」悄悄绕过）。

## §5 红线

- **已出图的书不得改画风 / 角色设定**——只改文字层；L4 里与画面绑定的行改完必须标「需重生成」。
- **授权由主模型向所有者要**；子代理只执行已授权动作，不得自行找所有者要授权或扩大范围。
- 台账写入只有脚本一条路（R15）；MCP 写接口留给脚本失效时人工兜底，不在常规流程使用。
