# 旁白 xlsx 审修/重写工作流

> 2026-09-15 大批量实测（White Crane白鹤 / Sika Deer梅花鹿 / Storm暴风雨 / Nice好 / Mid-Autumn Festival中秋节 / Grain in Ear芒种 + Get Up/Go Out/Horizon/How Are You/I Promise/I Understand/I'm Back/Nature/Nice to Meet You/Not Bad/Ocean/Puzzle/Rock/Sad/Sleep/Sunset Glow/Swimming/Thank You Very Much/Time/Toy/Year 等约 30 本）。与 picturebook-creator v5.5.0 八铁律并行：八铁律管「怎么改中文句子」，本 skill 管「xlsx 审修/重写任务的完整流程、格式基线与称呼铁律」。

## 一、两种模式（先判模式再动手）

| 模式 | 触发 | 英文列 | 交付 |
|---|---|---|---|
| **审修** | 用户直接发 xlsx | 只核不动 | `原名_修正版.xlsx`（MEDIA 直接发）+ 简短修正表 |
| **重写** | 用户发 7z/zip（故事简介.txt + xlsx）且明说「全部重写」；zip 文件名可能 GBK 乱码，按内容识别 | **一并重写**（覆盖"只核不动"） | 打包 `原名_修正版.7z`（内含 xlsx_修正版 + 简介_修正版.txt）MEDIA 回传 |

- 不问要不要，多文件按序处理，不逐个确认。
- 审修模式下**原句合格的行保留**（不为了改而改），修正表注明「N 行原句合格保留」。
- 重写模式下简介与旁白都是**整篇重写**，不是修句。
- **skill 修复铁律（2026-09-15 用户指令）**：用户要求清理 skill 中的过期内容时，**直接删除旧内容并替换为新规则**——禁止用「标记废弃/⚠️已废弃/以下仅存档」的方式把废弃内容留在 skill 里（用户原话：「不希望把废弃的过期的内容留在 skill 里，不要标记废弃，直接删掉」）；历史被否记录只保留一句病灶描述，不引用被否原句全文。
- **用户说「严格按照绘本创作 skill 规范流程来」= 流程重启信号**：当前批作废，从 L1 需求确认（严格 7 字段代码块）重走 L1→确认→L2 页面结构→确认→L3 标题+简介+旁白→确认→L4 提示词，每步停等确认不跳步（2026-09-15 Long time no see 实测：直接给旁白+L4 被纠正后从 L1 重走）。四步逐段输出模板速查见 `references/strict-flow-l1-l4-templates.md`；流程中用户回复「标题+简介」原文 = 直接采用锁定并进 L4，不再追问。

## 二、xlsx 格式基线（6 本实测一致）

- 表头行 1：`序号 | 英文 | 中文`；数据行 2-9。**写入行号 = 序号 + 1**（表头占 1 行，首写极易偏 1 行——白鹤实测错位一次）。
- 尾部杂字符（如 B15 `' | '`）必须清掉；回传前全表扫描确认杂项 = 0。
- 行 1 中文：`核心词中文 核心词英文！`（空格分隔，**无逗号**；全角！；英文大小写按书内既有形式——单字词不强转全大写（2026-09-16 用户判词「第一句全大写没有必要」）；短语类节名书内即全大写照旧）。
- **行1 英文大小写=书内既有形式，不强转全大写（2026-09-16 用户判词定版）**：用户原话「我认为第一句全大写，这个是没有必要的」——撤 v1.15.3「英文列行1全大写=新批次标准」，恢复 v1.9.0 口径（`Ocean!`/`NATURE!`/`Year!` 并存勿强改）。旁白是朗读稿，大小写不影响发音；图上文字三档约定（P1 认知页全大写等）属画面层，不受此判词影响。芒种类节名标题全大写不是「大小写规则例外」——是历史遗留没去处理，不构成规则依据。
- 行 2-8 中文：`正文，core word。/！`（全角逗号分句 + 句尾核心词）。
- 标点：中文列全角（，。！？）、英文列半角（, . ! ?）；中文列行尾内嵌英文核心词后的标点跟中文列走用全角（`I agree！`），英文列自身保持半角（`I agree!`——I Agree 全书 2-8 行统一实测）。
- 短语类核心词（Grain in Ear / Mid-Autumn Festival / Thank You Very Much）**每行完整保留不拆分**，大小写按书内既有形式。
- Nice 类「What is X?」书：中文避中英混句（`什么是nice，nice？❌ → 什么很棒呀，nice？✅`）。
- **重发旧 zip 行1格式可能退回**（Mid-Autumn 二次实测：退回「中秋节，MID-AUTUMN FESTIVAL！」逗号版）——处理 zip 时按定稿基线逐项核对行1（无逗号+英文全大写+全角！），退回即修回定稿版，不当作用户新偏好。

**核心词位置铁律（2026-09-15 三轮纠正 · 以用户芒种格式定版）**：用户原话①「核心词出现的位置要符合中文语境，不能读起来别扭」②「旁白的格式按照以下的格式重新修改」+ 芒种定版范例。主题/节气类书定版格式：
- 行1 标题行：`芒种 GRAIN IN EAR！`（中文核心词+空格+英文全大写+全角！）。
- 行2-8：`芒种麦子金黄金黄，Grain in Ear。` —— **主题词行首直连场景（主题词与场景间无逗号）+ 句尾英文 refrain 带标点**；refrain 标点与英文列行尾一致（陈述句=句号、感叹句=全角！）。
- ❌ 两版被否勿回退：句尾挂节名（`月亮圆圆的，中秋节！`——读起来别扭）；行首逗号话题位（`中秋节，月亮圆圆的！`——当轮即被芒种定版替换）。
- 动物/物品类例行旁白核心词句尾 refrain 照旧合格（`金丝雀住在笼子里，canary。✅`）——先判书的类型再定位置。

**主题色书文字颜色（2026-09-15 Colorful 实测，用户原话「标题是五颜六色，所有图中的文字应该也是有颜色的」）**：标题/主题为颜色概念时，L4 文字块弃默认珊瑚红+黑，改**彩虹多彩**——英文每个字母一色、中文每个汉字一色（红橙黄绿蓝紫轮换），并在 L4 文字模板制与尾部核对同步注明「本批文字均为彩虹多彩色」。

## 三、称呼铁律（用户 2026-09-15 原话：「'农人'这种称呼根本不符合小朋友的语境」）

**「农人」禁用**——小朋友语境里只有「农民伯伯」、小动物、具体的东西。同类书面腔（农人/渔人/樵夫/世人/旅人）一律换童语：
- 农人收割麦 → **农民伯伯收麦子**
- 定义腔（「芒种是最忙的节气」）→ 口语（**芒种真是忙呀**）

## 四、英文列处理规则

- 审修模式：默认只核不动。
- **英文本身是病句时必须改写**（重写模式必查；审修模式发现硬伤也要说明）：
  - 病句类型：核心词塞进主语位置 —— `Grain in ear wheat turns gold.❌`
  - 改法：正常句子 + 句尾短语核心词 —— `The wheat turns gold. Grain in Ear!✅`
  - 行 1 英文：全大写 + `!`（`GRAIN IN EAR!`）。
  - **审修模式行 1 大小写按书内既有形式保留**：Ocean!/Time!/Rock!/Year!（首字母大写）与 NATURE!/SWIMMING!（全大写）在第二批 18 本中并存，勿强行统一（2026-09-15 实测）。
- 英文改动需在修正表单独说明理由。

## 五、中文高频病灶对照（本批实例）

| 病灶 | ❌ 原 → ✅ 改 |
|---|---|
| 缺量词 | 白色的白鹤→**一只**白鹤；有鹿角→有**一对**鹿角；好漂亮的彩虹→**这道**彩虹好漂亮 |
| 单字形容词未叠词 | 长腿→**长长的**腿；浅水→**浅浅的**水；长脖子→**长长的**脖子 |
| 成对/单件量词 | 长腿→**一双**长长的腿；长脖子→**一个**长长的脖子 |
| 缺介词/方位 | 芦苇里走→芦苇**丛**里走；草地走→草地**上**走 |
| 电报语 | 两只白鹤在湿地→**湿地里有两只白鹤**；挂起彩虹→**彩虹挂天上** |
| 语序拗口 | 哗哗下大雨→**大雨哗哗下**；呼呼吹大风→**大风呼呼吹** |
| 中英混句 | 什么是nice，nice？→什么很棒呀，nice？ |
| 书面称呼 | 农人→农民伯伯 |
| 定义腔 | 芒种是最忙的节气→芒种真是忙呀 |
| 拟声漏译 | Boom!→**轰隆隆！**打雷啦（拟声对位） |
| 直接引语无引号 | 大家都夸，真可爱→大家齐声说：**"真可爱！"** |
| 定语后置拗口 | 小兔毛茸茸→**毛茸茸的**小兔（定语前置，全书句式统一） |
| "要"字说教 | 排队要排一长排→排队排**成**一长排；扣子要对准扣眼→扣子对准扣眼 |
| 感叹收尾缺语气 | 好美 Ocean！→好美**呀** Ocean！ |
| 同词相邻重复 | 铺满天空+铺满了晚霞→第二处换动词（把海面铺得亮闪闪） |
| 倒装拗口→叠词 | 胖得可爱→**胖嘟嘟**真可爱（Cute实测） |
| 儿语补全 | 小兔→小兔**子**、小鸭→小鸭**子**（儿语习惯） |
| 问候时段错位 | Good morning→你好呀❌ → **早上好呀**✅；Good evening→**晚上好呀**✅（时段词对位勿统称"你好呀"，How Are You 实测） |
| 英文末行句尾缺! | We're all back for yummy dinner→…dinner**!**（全书行尾均带!，末行对齐补齐，I'm Back 实测） |
| 引号内对齐英文感叹 | "真可爱！"→"真可爱**呀**！"（对齐 So cute!） |
| 颜色/整句漏译 | 玩具小汽车→**绿色**玩具小汽车；pick her up 整句漏→补"快把她捡起来" |
| 文化专名不直译 | A white rabbit on the moon→月亮上有一只**玉兔** |
| 量词错位 | 小熊拎着小鱼桶→拎着**一小桶鱼**（桶是量词非属性） |
| 岁/年误用 | 又长大一年→又长大**一岁**啦（生日论岁不论年，且避免与全书"一年"重复） |
| 名词堆叠电报 | 拼图最后一块，小熊脸→拼图最后一块**是小熊的脸** |
| 叠词塞状语位 | 大树高高长在大自然里→**高高的大树**长在大自然里（叠词只准定语位「XX的XX」，状语位拗口；09-15 Nature 用户单句否，改后与同书「清清小河/蓝蓝大海」句式对齐） |
| 句尾标点缺失 | 英文列 `Big trees in nature`→补句号（Nature 全书 7 处实测缺，补后与中文列尾标点对位） |

**叠词位置奥义（2026-09-15 用户单句纠错提炼，防再犯）**：
- 铁律1「单字形容词叠词化」的真实含义是**定语位叠词**：「高高的大树」「清清的小河」——叠词+的+名词。
- 同一个叠词放到**状语位**（动词前/后修饰动作）就拗口：「大树高高长在…❌」「跳得高高地❌」。补语位叠词另守 v5.5.0 §八A（飞**得高高**仅限该模式）。
- **自检方法 = 语序对齐法**：改完一句，拿同书相邻页句式当镜子——同书兄弟句是「清清小河流过…」「蓝蓝大海是…」（叠词定语前置），那这句也必须叠词定语前置；同书句式不一致本身就是病灶。
- **自检方法 = 朗读法**：整句大声读一遍，凡是需要换气才能顺下来的修饰语（「高高长在」），就是位置错了，不是词错了。

**为什么这条例子值得记住（教训）**：审修时该句因「叠词✓量词✓句完整✓」逐项达标而放行——但合格的是**成分**，不是**语序**。逐项自检查「有没有」，朗读/对齐自检修「顺不顺」；两者都过才算合格。用户单句点破后才发现，说明「逐项达标≠句子合格」，交付前必须加做语序朗读关。

叠词/量词密度守 picturebook-creator v5.5.0 §八B（全书 ≤3-4 处叠词定语）。

## 六、简介重写（小孩子语境一句话式 · 2026-09-15 两次被否定稿）

**铁律：简介 = 一句话故事预告——回答「谁 + 在这本书里经历了什么 + 结果怎样」。全句承载**一个连贯事件**（有先后/因果/承接的叙事线），画面是事件的素材不是简介本身；核心词自然嵌入，开心收尾。**（2026-09-15 Ocean 被否定版）

**⚠️ 判据澄清（2026-09-15 闸门2反对者审查后修正，勿再犯）**：
- Ocean 病句「浪花跳呀跳，海豚蹦得高高」的每个小句**语法上都主谓自足**——病根不在句法层，在**篇章层：多个场景零连接并列，没有共同事件线**。所以判据问的不是「主谓宾全不全」，而是「这些小句串不串成**一件事**」。
- 「是画面拼贴」的判别式：把小句间的逗号换成句号，若各句**仍各自成立、互不依赖**（浪花跳。海豚蹦。→ 各说各的）= 拼贴❌；若后句承接前句（认识了新朋友→所以笑哈哈）= 事件✓。
- **节气/时令类书例外定版**（芒种/Colorful 用户实测通过勿改）：节名本身就是「事件发生」的宣告（芒种到啦！），其后景列=同一节气的展开画面，收束句（最忙碌的节气到啦）完成事件闭环——这类书不按拼贴判。判别式：首句是否「XX到啦/XX节」宣告句 + 尾句是否回扣主题。
- 「画一幅」类砍宾语：判的是**信息完整性**（一幅什么？孩子不知道画的是什么）≠句法宾语缺失。

**简介四步定稿流程（2026-09-15 v1.14.1 事件完整性修正版，先走流程再出句）**：
1. **用一句话概括全书事件（主谓宾完整）**：通读 8 行旁白，写「谁 + 从头到尾经历了什么 + 结果/感受」——是**一个事件**的主线（有先后/因果/承接），不是抽 2 个画面拼贴。画面只是素材，主线才是简介的种子。自检：这句话能回答「这本书讲了什么」吗？
2. **选主角**：全书贯穿的动物/人物当主语（小猫咪/小兔/太阳）；无单一主角时取集体主语（小动物们），禁无主语句。
3. **写完整叙述句（主谓宾自足）**：每个小句必须主+谓+宾/补完整且自足（认识了新朋友✓/蹦出浪花来✓），孤立主谓片段=病句（浪花跳呀跳，海豚蹦得高高❌——动作无落点、两句零连接）；不用光秃动宾（画一幅❌）。
4. **嵌入核心词 + 短收尾**：破折号后核心词 + 孩子口语收尾（笑哈哈）。

**简介审计清单（交付前逐项过，任何一项不过 = 重写）**：

> ⚠️ **清单定位（2026-09-15 13 例实测后定版）**：清单是「审什么」的提示，**不是自动判别器**——把判别式写成字面关键词规则实测 8/13（5 条误伤/漏放：定稿范例被误杀、Ocean 病句被字面「得」字骗过）。判定「过不过」必须靠**语义审查**（闸门2：读全文理解小句间有无叙事推进），清单管覆盖面、闸门管判定，两者不可互替。

```
[ ] 是故事预告吗？（听完能回答「这本书讲了什么」；只答出有哪些画面 = 重写）【最高优先·语义判】
[ ] 是一个事件吗？（句号替换法辅助自检：小句间逗号换句号后各句互不依赖且无归纳收束 = 画面拼贴嫌疑 → 交闸门2语义审）
[ ] 有主角吗？（主语是具体人物/动物，不是无主句/任务清单）
[ ] 句间有承接吗？（后句依赖/推进前句：挤牙膏→刷牙✓；纯并列罗列 = 列举体❌）
[ ] 是动词版元素列举吗？（动词/动宾短语 ≥3 连排 = 大嘎大嘎马甲，❌）
[ ] 是任务清单吗？（「去…：摸…、看…、数…」结构 ❌）
[ ] 宾语信息足吗？（「画一幅❌」→「画了一幅画✓」；禁为凑节奏砍宾语）
[ ] 大声朗读：像 4 岁小孩说的话，还是像大人编的口令？
[ ] 与旁白一致吗？（简介情节 ⊆ 旁白实拍场景，不挂空；声称一致必回旁白原文逐条验证）
[ ] 核心词嵌入后无中文复读？收尾词孩子嘴里说得出？（笑哈哈✓ 笑开怀❌）
[ ] 禁说教句/说教收尾？（「XX的孩子最棒」❌）/ 禁发现式感叹腔？（「世界原来这么多彩」❌）/ 禁拖沓凑数？（运营话术/复读释义 ❌）
[ ] 节气/时令类书：节名宣告句（XX到啦！）+ 收束回扣主题 = 事件闭环，勿按拼贴误判
```

**为什么有这个清单（教训）**：Nice to Meet You（蹦蹦跳跳交朋友）与 Not Bad（画一幅搭一搭唱一首跳一跳）两连否——病灶都是「逐项检查全过、整句不合格」。成分/语序/结构三层：成分查有没有（叠词量词）、语序查顺不顺（朗读）、**结构查像不像孩子说的话（主角+连接+画面）**。简介是创作题不是检查题，先走四步流程再出句，出句后过审计清单。

**单词类书**：`<叠词动作钩子>！+ <主角+叠词结果> + —— + 核心词英文 + 叠词短收尾！`
- 定稿范例（Brush Teeth）：`刷呀刷！小猫咪刷出亮晶晶的小白牙——brush teeth，天天刷，笑哈哈！`
- 定稿范例（Cute）：`毛茸茸的小兔，圆圆的小鸡，布娃娃笑眯眯——大家都好可爱好可爱，cute！`
- 定稿范例（Get Up）：`起床啦！太阳爬上山头，金光洒进小窗——get up，美好的一天开始啦！`
- 定稿范例（Balloon）：`吹呀吹，大红气球鼓起来，飞呀飞上蓝天——balloon，越飞越高真开心！`
- 定稿范例（Colorful）：`彩虹挂天边，红橙黄绿一道桥——colorful，世界五颜六色真好看！`
- 定稿范例（Nice to Meet You）：`握握小爪子！小兔认识了新朋友——nice to meet you，笑哈哈！`（❌ 前版「小兔蹦蹦跳跳交朋友——nice to meet you，笑开怀」被否，用户判词「口语适口性差很多」：①「蹦蹦跳跳交朋友」=叠词+连动挤一句，节奏赶、拗口；「认识了新朋友」=口语叙述句，孩子说话的方式 ②「笑开怀」书面成语残片，孩子嘴里说不出。**奥义：适口性≠词藻量——叠词不是越多越好，简介前半段宁可朴素叙述句，也不塞「叠词+动作」压缩包；收尾词自查「孩子嘴里说得出吗」**）
- 定稿范例（Not Bad，四步流程实测通过）：`小动物们样样自己来——not bad，今天真棒呀！`（无单一主角的书取集体主语「小动物们」；「样样自己来」概括旁白 6 事且删核心词后「真不错」直译复读）。❌ 被否记录（未交付即拦）：`画一幅，搭一搭，唱一首，跳一跳——not bad，真不错，今天真棒呀！`——动词版元素列举（4 个光秃动宾逗号连排）+ 无主角（幼儿园活动单）+ 砍宾语凑三字节奏 + 核心词后「真不错」直译复读。**四步流程+审计清单经此例首次端到端验证。**
- 定稿范例（短语类 I'm Back）：`我回来啦！小熊提着小鱼桶蹦进门，一家人香香甜甜吃晚饭——I'm back，回家的声音最好听！`
- 2026-09-15 回传验证：How Are You（问呀问！）、I Promise（拉钩钩！）、I Understand（点点头！）三本按本公式重写回传，未收否决；同日第二批 18 本短语/情绪/自然类 zip（I'm Back→Year）全部按本公式执行。

**节气类书**：`<主题>到啦！+ 叠词景×3 + —— + 核心词 + 收尾！`（芒种定稿，用户未否）
- 例：芒种到啦！麦子黄澄澄，秧苗绿油油，梅雨哗哗下——Grain in Ear，最忙碌的节气到啦！

1. ❌ 纯故事描述+说教句（`小猫咧嘴露出亮白牙…天天刷牙的孩子牙最棒！`）——用户：「这是教孩子认识单词的英文单词绘本，简介要重写」。病灶四条：缺核心词；写结果态不写过程（旁白全是动作线）；说教句隐含比较；「咧嘴」生硬。
2. ❌ 运营公式（`跟着绘本一起学「X」——场景列举，8个场景反复磨耳朵…看完告诉宝宝：…`）——用户：「太拖沓，太冗长，强行凑数，很烦人。要用小孩子的语境」。此为 douyin-bilingual-picturebook-publishing 旧公式，已两处同步推翻，勿再使用。

**简介病灶分析框架**（用户问「简介有什么问题」时按此答）：缺核心词 / 结果态vs过程 / 说教句 / 生硬用词 / 运营话术凑数 / 说教收尾（「分享的气球最快乐」——价值训导）/ 发现式感叹腔（「世界原来这么多彩」——「原来」=大人揭秘口吻）/ 简介情节与旁白动作线脱节 / 核心词被动作吞没（「叫醒大家起床」——get up 被吞进太阳动作）/ **书面成语腔收尾**（「笑开怀」——用户原话「什么鬼东西」，3-6 岁口语里不存在；收尾词必须从孩子嘴里说得出来：笑哈哈✓笑眯眯✓，书面四字腔=大人代笔感）/ **叠词堆砌赶节奏**（「蹦蹦跳跳交朋友」——叠词+连动挤一句朗读拗口；适口性>词藻量，口语叙述句「认识了新朋友」反而更顺，简介句≠旁白句：旁白单句短可带叠词，简介一句话承载全书更要疏朗）。

## 七、简介 QA 双闸门（Powerflow × QA Test 结合 · 仅重写模式触发）

**触发**：重写模式（简介重写产物）+ skill 修订方案。审修模式不走闸门（只核不动）。

**L3 现场生成触发器（2026-09-18 do 实测补 · 闸门2 三轮放行）**：L3 备选生成阶段跑「三问终检」（素材问/自然语问/落点问，见 picturebook-creator §3.2）——它是现场自答触发器，**不替代本双闸门**：闸门2 语义审查仍是唯一判定权威，三问只负责把思考提前到生成时、防「写完才想起」。重写模式产物照走双闸门不受影响。

```
四步定稿流程产出候选 → 【QA闸门1·code_review型】逐条验证清单实测 → 【QA闸门2·plan_review型】反对者攻击（多轮直到无致命/严重） → 交付
```

- **闸门1（code_review型）**：把审计清单逐项写成验证（每条：检查点/预期/验证方法=回读旁白原文/朗读），逐条过，FAIL 就修，修复落回正文
- **闸门2（plan_review型）**：**能 spawn 时必 spawn 独立反对者子 agent**（delegate_task，角色分离：审查 agent ≠ 写作 agent，只审不改，每条标严重度，1-10 总评）；spawn 不可用时降级为同上下文自审并**在交付说明中注明「闸门2=自审降级」**。致命→改候选重新过闸门1；严重→逐条回应后才可交付；中等→酌情；轻微→记录。**闸门2 是唯一的判定权威**：审计清单只提示「审什么」，过不过由反对者读全文语义判断——13 例实测字面规则 8/13、语义判别 13/13
- **多轮闸门**：首轮报告有致命/严重 → 修复后**再跑一轮**反对者，直到无致命/严重（Powerflow：不是一轮放行）
- **15维度幻觉自检**：声称「与旁白一致」「收尾呼应」→ 逐条回旁白原文验证，防「我以为对位了」（派单/写规则前同样适用：声称已做→grep 验证，声称 schema→实测）

## 七b、openpyxl 坑（必读）

- `cell(row, column, value=None)` = **无操作**，清空必须 `cell(r, c).value = None` 直接赋值（白鹤实测两次踩坑）。
- 写入后**必须回读全表验证**：表头、8 行数据、junk 计数。
- 保存后核对文件存在 + 大小，再 MEDIA 回传。
- **zip 包文件名 GBK 乱码**（Brush Teeth/Cute 实测）：解压出 `╣╩╩┬╝Є╜щ.txt` 类乱码名。**实测可靠解法（2026-09-15 How Are You/I Promise/I Understand 三连包全部成功）**：Python zipfile 解包时对每个条目名执行 `name.encode("cp437").decode("gbk")`（异常则保留原名落盘），解出的中文名直接可用；解码失败再按内容识别：*.txt=故事简介、*.xlsx=旁白表。
- **文件名≠内容校验**（Swimming 实测）：打开先核对 sheet 内容与文件名主题一致——模板复用导出会装错内容（Swimming游泳.xlsx 内装的是 Sleep 全表，逐单元格比对确认）。不一致时：按实际内容回传已定稿修正版并明确说明，请用户重发真表；不要按文件名硬改错内容。
- **sheet 名模板残留**（2026-09-15 三连包实测：How Are You/I Promise/I Understand 三本 sheet 名全为 "Archie's kite"）：回传前检查 sheet 名，残留模板名 → 重命名为书名并在修正表注明。
