## 一、标题判据（B：释义逐字 + 量词/口语虚词白名单）

**输入三件**（台账三列，缺一不进 L3）：核心词｜词型｜中文释义（词典义项，不带量词/括注/词性）。

**形态**：中文 `[量词或口语虚词]<台账释义>[口语虚词]，<核心词>`；英文沿用现行规则（简短口语、含核心词、Title Case 封面）。

**判据（七条，全机检）**

| # | 判据 | 会红的例子 |
|---|---|---|
| E1 | 英文列含核心词（词形取 `wordforms.py`） | `Up the Hill` 不含 high |
| E2 | 中文列含核心词形态 | 「星星」配 `Star`（台账真例 B260） |
| E3 | 中文列无括注 | 「扇子（Phonics），fan」 |
| E4 | 含词后中文 ≤12 字（兜底） | — |
| E5 | 无方法论禁词 | 「自然拼读」 |
| **G1** | **中文列必须含台账释义逐字** | 「凑近一点，Whisper」（释义「小声说」）|
| **G2** | **去掉释义与核心词后，中文字符只许落在白名单**（量词/指代/口语虚词；**不含任何形容词性修饰**） | 「小锅煮汤，Pot」（释义「锅」）→ 残留「小汤煮」；「一枚小硬币，Coin」→ 残留「小」（**小字病**） |
| **P1** | **词型非动作类时，英文不得用核心词动词屈折形或祈使尾** | `Fan it!`（名词）、`Fanning` |

**本判据不证明什么（必须写在规则里）**
1. 只证明「标题与台账锁定字段一致」；**释义本身对不对、词型与释义是否匹配、标题与画面是否同一义项，都不机检**。
2. 释义由模型写给模型判 = 自证循环。所以 L1 必须让所有者**逐字确认释义原话**，并把这句原话与写入台账的释义做逐字对账。
3. 词型—释义—标题三者一致性靠 L1 一次锁死 + 审计复核，不靠这几条判据。

**校准集（先证后写，2026-11-22 订正版）**：台账 13 条历史标题 → 红 11 / 绿 2；5 条错例 → 5/5 命中。
**但台账历史标题不是「应该绿」的基准**（其中「一枚小硬币」本身含**小字病**，所有者早就不满意）：它只用来列「要改哪些书」。判据不替创作定措辞——`小锅煮汤` 的正解是「重写这句话」还是「锅，pot」，由创作侧/所有者定，判据只报「不合规 + 命中哪条」。
明细与命令见 `docs/证据-标题判据校准-2026-11-22.md`。

## 二、执行者形态（所有者裁定 A）

| 动作 | 执行者 | 为什么 |
|---|---|---|
| 写台账（归档/改写/状态/备注） | **主模型直接跑 `scripts/notion_archive.py` 一条命令** | 确定性脚本，工具面只有「跑命令」；再套一层子会话只会增加判断次数 |
| 写入后的独立回读 | **子代理（重活槽）** | 执行者与核对者分离；子代理只 fetch 页面、回报状态/备注/块数原文 |
| 方案 / 决策 / 审计 | 子代理（重活槽；第二路轻活槽） | 判断力密集 |
| L4 整本装配 + 五道门禁连跑 | 子代理（轻活槽） | 长链路、多工具调用 |
| 创作（标题/旁白/简介/L4 文案） | 主模型 | 文笔是它的强项 |

**「弱工具」判定改外部静态条件**（不许自评）：会话主模型 ∈ 适配包 §8 的「创作型/工具弱」名单（当前 = `gemma4:31b`）→ 按上表委派；否则主模型可自干，但仍须回读。
**路由核对改一条命令**：`python tools/model_probe.py --newest 3`，读会话档的 `agentProvider/agentModel`；不认子代理报告里的 `MODEL:` 自述。
