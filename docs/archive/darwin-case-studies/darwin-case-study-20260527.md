# Darwin实测案例：picturebook-creator 优化记录

## Session: 2026-05-27

## 关键发现

**问题**：skill规则正确，但主agent执行时未遵循。

**根因**：
- skill规则写得清楚，但缺少强制执行机制
- 主agent自评有偏差（觉得自己输出正确，实际丢了目标词）
- 一次性输出多步导致错误累积

## 教训

1. **skill规则正确 ≠ 执行正确**：需要enforcement（强制自检），不能只靠规则描述
2. **分步确认是质量保障**：一次性输出让错误累积，分步确认可以及早发现
3. **子agent实测是金标准**：主agent自评有偏差，Darwin的子agent对比才能发现真实问题
4. **旁白修改场景**：原旁白满足核心原则时，只微调不重构

## Session:2026-05-29 — 测试 prompt污染陷阱

###现象

跑 picturebook-creator 的 cat 测试时，子 agent 输出全部旁白的中文列都丢了 `cat`：

|序号 |英文 | 中文 | 结果 |
|------|------|------|------|
|1 | CAT! |猫咪 CAT！ | ✅ |
|2 | A cute cat | 可爱的猫 |❌ cat丢失 |
|3 | A cute cat walks | 可爱的猫在走 |❌ cat丢失 |

第一反应：skill 有 bug，应该改 skill。

###真相

skill 没 bug。错误在**测试 prompt 的 `context`字段**。

当时写的 context：
```
"请输出旁白表格，中文旁白格式为 [完整中文翻译] [英文核心短语]。
注意检查中文叠词自然度。"
```

子 agent看到 context里有「中文旁白格式要求」，按字面理解执行——把英文短语全部丢到英文列，中文列只留「猫咪/可爱的猫」。而 skill 里写的「每行中文旁白必须包含目标词英文」反而被忽略。

**关键观察**：子 agent优先服从 context 里**更具体、字面更明确**的指令，而非 skill 里**更通用**的规则。

###诊断三问

发现输出不符合 skill规则时，先问：

1. **测试 prompt 的 context字段是否引入了额外约束？**（最常见原因）
2. **子 agent是不是在 context约束下做出了"符合字面但不违反 spirit"的妥协？**
3. **如果去掉 context里的约束，重新跑会通过吗？**

如果第3问答案是「会通过」，说明是 prompt污染，不是 skill 问题。

###修复

- **不动 context**，改为优化 skill本身
- 把「双语同现」从自检清单的 #5移到 **#1位置** + 加粗 +⚠️标记
- 在 L3 输出前加「前置警告」章节，强调目标词必须在每行出现

修复后重新跑 cat 测试，3/3全部通过。

### 给 Darwin流程的教训

测试 prompt 的 `context`字段**只能描述用户场景**，禁止写规则约束：

|❌错的写法 | ✅正确的写法 |
|------------|------------|
| "中文旁白格式为 [完整中文翻译] [英文核心短语]" | "用户场景：3岁宝宝学 cat 这个词" |
| "注意检查中文叠词自然度" | （什么都不写，让 skill 自己检查） |
| "请严格遵循 X、Y、Z规则" | "请按照 picturebook-creator skill 的规范执行" |

需要强调的检查项应该通过**修改 skill 让规则更醒目**来实现（前置警告、加粗、#1位置），而不是在测试 prompt 里复述规则。

### 与2026-05-27案例的关系

旧案例的结论是「skill规则正确但执行偏差」，本节是补充「偏差来源也可能是测试 prompt本身」——两者结合才能完整归因。Darwin评估时如果发现子 agent跳过某条规则，先排除 prompt污染再改 skill。
