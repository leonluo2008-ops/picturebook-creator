## 新增发现（v5）

### P40 · 风格切换可发生在 L1/L2/L3 都确认后（NEW 2026-07-17 v5）

**实测来源**：本会话 woodpecker 会话流程：
1. L1：用户给 Eric Carle 拼贴风 → 我确认 ✅
2. L2：输出 10 页结构 → 用户确认 ✅
3. L3：输出标题/简介/旁白表 → 用户确认 ✅
4. **用户在选标题+简介之前**，又发新消息把风格改成"蜡笔手绘童趣风"

**问题**：之前 confirmation-protocol §四说的是"中途切换"，假设是 L2 之前的切换。本会话发现风格切换可以发生在 **L3 已经确认后**。

**规则升级**：
- 风格切换可发生在 L1/L2/L3/L4 任一步骤之前
- 切换后必须重新评估：
  - L2 页面结构：**通常不需要改**（风格不改变页面结构本身）
  - L3 旁白：**不需要改**（旁白是文案）
  - L4 生图提示词：**全量重写**（风格锚点字段每个提示词都要换）
- 当用户切换风格时，agent 必须：
  1. 立即确认切换意图（避免误判）
  2. 不需要重做 L2/L3
  3. 重新输出 L4 全套

**沉淀位置**：picturebook-confirmation-protocol §四 风格切换段升级

### P41 · 批量连续同类型目标词的"角色外观轮换"原则（NEW 2026-07-17 v5 · 中优先级）

**实测来源**：本会话连续做 6 本鸟类（seagull/magpie/crow/pigeon/white crane/swan），用户未触发"角色雷同"反馈。但 picturebook-creator SKILL.md「⚠️ 角色外观一致性强制规则」段说"同一本内一致，不同本之间要多样性"。

**问题**：批量连续同类型目标词时，agent 自动遵守"本内一致"，但每本主角外观之间高度相似（都是圆眼睛+羽毛），可能让用户产生视觉疲劳。

**规则**：
- 当会话内已连续做 ≥ 3 本**同类型**目标词（鸟类/哺乳类/花卉/水果），agent 在 L2 输出前主动提醒用户：
  - "本会话已做 N 本[类型]绘本，第 N+1 本建议更换主角外观细节（如眼睛形状/羽毛层叠方式/鸟喙比例）"
- 提醒格式：放在 L2 输出表上方 1-2 行
- 用户可以选择"同意轮换"或"维持现有模板"
- 默认走"同意轮换"，因为多样性是 picturebook-creator SKILL.md 原有铁律

**沉淀位置**：picturebook-creator SKILL.md「⚠️ 角色多样性（2026-06-07用户强化）」段升级

### P42 · L4 输出前 7 项核对清单应作为模板（NEW 2026-07-17 v5 · 低优先级）

**实测来源**：本会话我执行了 18 次「L4 输出前 7 项核对」清单，每次都是手抄一遍。清单内容固定：
1. 封面页（3:4，1 张）
2. 认知页（16:9，1 张）
3. 语境页（16:9，N 张）
4. 结尾互动页（16:9，1 张）
5. 总张数对账
6. 每条记录四字段
7. 代码块外无任何文字

**问题**：7 项核对是固定模板，不应该每次手抄，应该作为 L4 输出前的自动前置段。

**规则**：
- L4 输出前必须先输出 7 项核对（即使是模板）
- 7 项核对用 markdown checkbox 格式 `[ ]` 让用户/agent 都能快速过
- 用户不需要对 7 项核对回复——这只是 agent 的内部纪律提示

**沉淀位置**：picturebook-creator SKILL.md 步骤 L4「⚠️ L4 输出前 7 项核对」段升级

### P43 · "删第 N 句"（非结尾）应触发"换语境"默认修复（NEW 2026-07-17 v5）

**实测来源**：本会话多次用户说"第 N 句换语境"，agent 每次都提供了 4 选 1 选项给用户，但实际用户多数直接选 D（最后一个）或者回"确认"。

**问题**：每次都问 4 选项浪费用户耐心。

**规则升级**（P33 v3 旁白结构检测标准化 + 本会话观察）：
- 用户说"换语境"且未指定具体方向 → **默认走"换时段/换数量/换动作"中的 1 个 + 提供 2-3 个具体备选**（不是 4 选 1）
- 默认时段型（D）是因为时段型最不影响其他维度（颜色/形状/数量都保留）
- 减少 4 选 1 压力，提升批量效率

**沉淀位置**：picturebook-creator SKILL.md L3「⚠️ P33 旁白结构检测 + 修复 A/B/C 路径标准化」段升级

## v5 实测验证的旧规则

### 验证 P37（动物主线 ABCD 默认 C）· v5 实测

**实测**：本会话剩余动物目标词主线选择
- arctic fox → 用户选 B（雪地生态）
- sika deer → 用户选 C（森林生态）
- white crane → 用户选 C（湿地生态）
- swan → 用户选 B（水上滑行）
- crow → 用户选 C（坚持原词+避开不祥）

**问题**：本会话动物主线选择中只有 50% 是 C（生态场景），其余选 A/B/D。

**修正**：P37 v4 默认 C 的规则过于激进——应该默认 C 但明确告知用户选择是开放的。

**新版本**：
- 默认走 C（生态场景）
- 但下一轮顶部写明"已默认走 C（生态场景），本会话中 50% 用户选了非 C 路线，如有不同请告知"
- 降低对用户选择的预期压力

**实测**：
- magpie 第 9 句复数（已在 v4 记录）

**新观察**：复数冲突在批量绘本里**是高频问题**——用户写旁白时往往不自觉用复数（"两只白鹤"→ two cranes），但领读绘本要求目标词保持单数。
