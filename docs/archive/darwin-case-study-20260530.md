## Round 1 优化

### 改动内容

**位置：** 工作流总览图（模式A/B各自的第一步）

**改动前：**
```
步骤1 需求确认(主题/主角/风格/路径)
步骤2 标题+简介创作
...
步骤L1 领读需求确认
  ├─ 输出需求确认表
  └─ 必须等待用户确认后才能进入步骤L2
```

**改动后：**
```
步骤1 需求确认(主题/主角/风格/路径)
  └─ ⚠️ 必须等待用户确认后才能进入步骤2
步骤2 标题+简介创作
  └─ ⚠️ 必须等待用户选择后才能进入步骤3
...
步骤L1 领读需求确认
  ├─ ⚠️ 输出需求确认表
  ├─ ⚠️ 必须等待用户确认后才能进入步骤L2
  └─ 禁止跳过确认直接输出后续步骤
```

### 优化理由

- 检查点规则散落在各步骤细节中，容易被忽略
- 工作流总览图是用户/子agent第一眼看到的结构，总览无⚠️则整体缺失
- ⚠️符号在视觉上形成"阻断墙"，降低跳步骤风险

## 待继续优化方向

### P1（+5分预期）：领读L3规则去嵌套

问题：L3本身约300行，层层叠规则（双语同现→禁止格式→逐行核对→格式规范），容易丢核心约束。

建议：把L3的规则表（8项自检）提升到L3开头作为唯一检查入口，不再分散引用。

### P2（+3分预期）：资源引用路径加存在性校验

引用文件（`references/style-library.md`等）存在但无校验步骤，建议在步骤1风格选择前加"路径校验"动作。

### P3（+4分预期）：检查点规则独立成节

当前检查点规则散在步骤描述末尾，建议独立一节「检查点汇总」，供快速查阅。
