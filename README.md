## 两种模式

### 故事模式（Story Mode）
讲一个有叙事弧线的故事，适用于：故事绘本、冒险绘本、情感绘本、睡前故事。

**工作流**：需求确认 → 标题+简介 → 旁白 → 生图提示词

**路径分流**：
- 路径A（无固定角色）：需求确认 → 标题+简介 → 旁白 → 生图提示词
- 路径B（有固定角色）：需求确认 → 标题+简介 → 旁白 → 角色定型 → 定妆确认 → 生图提示词

---

### 领读模式（Phonics Mode）
教孩子认读、拼写特定单词，适用于：自然拼读绘本、单词认读、phonics、学单词。

**工作流**：L1 需求确认 → L2 页面结构 → L3 标题+简介+双语旁白 → L3.5 口语门禁 → L4 生图提示词 → L5 Notion 归档

**逐步确认，禁止跳步**——信息齐了也必须从 L1 顺序走。

## 领读模式核心能力

1. **L1 需求确认**：目标单词、年龄、中文核心词、画面风格
2. **L2 页面结构**：9 页固定结构 —— 封面认知页 → P1 字母拆解 → P2 拼读示范 → P3–P6 四个语境页 → P7 词族扩展 → P8 互动练习（词族为空、或同拼写的词读音不同，就跳过词族页，用额外语境页补足 8 内页；词族两个干净的同族词即可，宁少不凑）
3. **L3 标题+简介+双语旁白**：标题出 **3 个备选**、简介写 **3 条备选**，用户明确选定后才进 L4；简介是**说给小朋友听的两句话**（1–2 句、单句 ≤30 字），不介绍这本书教什么、不承诺学习效果，三条落点都落在孩子身上：画面上正在发生什么 / 孩子会跟着做的身体动作 / 合上书还剩下的一句话
4. **L4 生图提示词**：四字段结构（旁白:比例:页面类型:生图提示词），全局风格锚点，**主角外观只写一行、不逐页复述**，全文必须是一个连续代码块
5. **L5 Notion 归档**：选定标题与简介确认后，写入排产台账

## 批量模式（连续下单）

用户一次只丢一个核心词，中间不再重复说年龄、风格、页数结构。**减少的是用户的输入，不是确认环节。**

- 能省的：年龄、风格、九页结构、核心词小写、旁白落点 —— 按默认值直接定
- **不能省的**：标题 3 选 1、简介 3 选 1，用户没选定就不许进 L4、不许归档
- 禁止：只给一条标题就归档；只给一条简介就进 L4；用户没回话就先写进 Notion

## 角色可行性审查（L1 选角色时 / L4 出提示词前）

**先列动作，再选角色。** 角色必须能完成全书每一页的动作，不是只完成封面。

1. **列动作清单**：九页定稿后，逐页写出角色必须做的动作，并注明用到哪个身体部位（抓 / 握 / 举 / 踮 / 攀 / 够 / 指向）。
2. **对肢体**：有没有能抓握的手或爪？能不能踮脚？能不能攀爬？能不能把肢体举过头顶？体形够不够得着？
3. **做不到就改**：换角色或改这一页的动作，不许靠"看着差不多"糊，也不许在提示词里硬写它做不到的姿势。

| 角色类型 | 抓握持物 | 举过头顶 | 攀爬 | 风险 |
|---|---|---|---|---|
| 人类儿童 | ✓ | ✓ | ✓ | 最稳 |
| 有前爪的（灵长 / 浣熊 / 松鼠） | ✓ | ✓ | ✓ | 写「前爪」更稳 |
| 蹄类（鹿 / 马 / 牛 / 长颈鹿） | ✗ | ✗ | ✗ | 风筝、举手类动作必崩 |
| 象 | 仅鼻端可卷 | ✗ | ✗ | 能卷不能捏 |
| 鸟类 / 有鳍的 | ✗ | ✗ | ✗ | 无法持物 |
| 无肢（鱼 / 蛇） | ✗ | ✗ | ✗ | 只能贴附 |

换角色时同步改简介、旁白里写死身体的句子（"伸长脖子""用鼻子卷"）。

**出图稳定性二审**：复合持物动作（卷起 + 举起 + 凑到嘴边）生成模型容易画崩；有手 / 前爪的角色端杯拿壶成立，没有抓握肢体的角色（象鼻、鸟喙）喝水改用河边自然场景——判据是这个姿势对这个角色是否日常可信，不是禁止用容器。配角也要过同一份动作清单。

## 语法与文字规范检查（标题 / 简介 / 旁白全覆盖）

三处都要过，缺一处等于没查。

| 类别 | 要求 |
|---|---|
| 英文大小写 | 句首大写；`I` 永远大写；`Mom`/`Dad` 大写；句首的字母组合首字母也大写（`Gh is silent`）；目标词按句中小写 |
| 英文标点 | 每句有句末标点；一页多句用句号断开；破折号前后各一空格；一页最多一个感叹号 |
| 中文标点 | 一律全角，不混半角；目标词前用中文逗号；中文行首不直接摆小写拉丁字母（改写句式或加引号） |
| 语法 | 主谓一致、单复数与冠词、时态统一（默认一般现在时）、句子完整 |
| 发音标注 | 只用「字母名」或「常见拼写块」（`igh says I`、`ey says ee`、`gh says f`），禁 IPA，不许用单个字母冒充别的音；全书口径一致 |
| 中文旁白落点 | 目标词收在句尾自然落点，不许卡进名词 / 动词短语中间（「回家的 way」）；中文列不出现英文教学短语，拼读表述只用中文句式 |
| 朗读 | 每页出声读一遍；英文一页 ≤8 词，中文一句 ≤30 字 |

## 双语旁白结构（核心）

| 旁白 | 内容 |
|-----|------|
| 英文旁白 | 完整原句（含目标词），供孩子跟读 |
| 中文旁白 | 完整中文翻译句 + 目标单词并列 |

- 中文旁白格式：`[完整中文翻译] [目标词]`，例：`这是我的叔叔，uncle`
- **只绑定目标单词本身**，不绑定完整英文句
- 目标词位置以**中文自然**为准：句尾最常见（逗号分隔），句中亦可；**不得孤立成词**，也不要为凑句尾把中文掰拗口
- 中英文意思一一对应，中文不得多加英文没有的内容
- 标点严格对应：英文 `.` → 中文 `。`；`!` → `！`；`?` → `？`

## L4 角色描述的写法（本版最重要的一条）

```
✅ 正确：主角外观: 一只浅棕色的小棕熊，穿天蓝色白条纹短袖上衣、浅黄色短裤、橙红色小凉鞋
        5. 角色一致性: 统一外观描述

❌ 已废弃：每条提示词中主角外观描述必须完整重复，不能省略
          （每页复述整段五官 → 逐页漂移 + 手部结构崩坏）
```

**不要写**：虹膜渐变、上睑睫毛线、眼睛占脸比例、牙齿、腮红、肢体粗细。
**要写**：物种 + 主色 + 服装三件（上衣/下装/鞋），一行写完，只出现在【全局设计约定】。
**表情**：每页只写 2–3 个具体小动作（眉毛/嘴角/脸颊），不复述五官结构。

## L5 Notion 排产台账归档（v10.1.1 可执行化）

领读模式 L4 生图提示词确认后**自动触发**，把创作产出回填到 Notion「绘本排产中控台 → 排产台账」。

行处理规则（用户 2026-10-23 纠正）：

| 情况 | 行为 |
|---|---|
| 台账**已有**该核心词的行 | 直接复用该行，**绝不重复建行**（幂等） |
| 台账**没有**该核心词的行 | **自动建行**：排产号取全库最大 `B###` +1，词型可选，状态列留空交给排产流水线 |
| 该行正文已有「📚 创作产出」 | **默认拦截**防重复归档；确认补档（L4 重出）加 `--force` |
| 命中多行 | 停下，用 `--page-id` 指定，禁止猜 |
| 状态列 | 一律不动 |

```bash
python3 scripts/notion_archive.py --word day --locate                    # ① 只读定位行
python3 scripts/notion_archive.py --word day \                          # ② 归档正文
    --title '选定标题' --brief '选定简介' \
    --narration /tmp/narration.md --l4 /tmp/l4.md
# --dry-run 干跑 / --page-id 指定行 / --attr-title --attr-brief 属性回填（默认关闭）
# --no-create 禁止建行 / --force 允许重复追加 / --word-type 词型 / --sched-no 指定排产号
```

写入结构（脚本内置，末尾自动回读校验，缺失即 exit 1）：

| 顺序 | 块 | 内容 |
|---|---|---|
| 1 | `heading_2` | `📚 创作产出（YYYY-MM-DD 归档）` |
| 2 | `paragraph` | 选定标题 / 选定简介 |
| 3 | `heading_3` + `table` | 双语旁白（3 列，首行表头） |
| 4 | `heading_3` + `code` | L4 生图提示词全文（**一个** code 块；超 1900 字在同块内拆多条 rich_text，不拆块） |

前置条件：`NOTION_API_KEY` 在 `~/.hermes/.env`（frontmatter 已声明为必需环境变量），台账库已 Connect 到该 integration。

> 台账定位三段式（中控台页 → child_database → `GET /v1/databases/{id}` → `data_sources[].id`）已内置于脚本并带自动重新发现；`child_database id ≠ data_source_id`，拿前者直接 query 必 404。
